# 小鑫《多频道求救》MV 导演方案与制作总计划 V0.1

## 1. 对歌曲的理解

这首歌表面是一段末日救援通讯，真正写的是“小鑫式承诺”的代价：他不是不在乎，也不是故意失约；他把每个求救都当成必须答应的请求，于是没有任何人得到明确的优先级。最扎心的不是“他没有出发”，而是他一直在跑、一直给证据、一直安慰，直到路线真的只能选一条。

MV 的核心句不是“SOS”，而是“脚却停在岔路口”。因此画面不应做成普通丧尸动作片。前半段要让观众相信他真的是一个可靠、忙碌、带伤还在奔跑的救援者；后半段才揭示，他的奔跑并没有解决选择问题。

## 2. 导演阐述

**导演命题：一个人可以同时真心想救所有人，却仍然因为不肯说“不”而辜负所有人。**

视觉弧线为：

`按下通话键 → 封门与奔跑 → 用照片证明自己 → 四路求救叠加 → 奔向岔路 → 脚步停住 → 无线电独自闪烁 → 全黑`

开头先给无线电和手，不急着完整露脸；观众先通过声音认识他。Verse 用车灯、地图、奔跑和他轻松的表情建立可信度。Pre-Chorus 把空间从城市压缩成一条只能通一辆车的隧道。Chorus 不靠更多丧尸提高强度，而靠四个频道同时闪烁、镜头越来越近、选择越来越具体。最后不解释他是否活着，也不替他选路线，只留下一个无法回答的呼叫。

## 3. 叙事结构

### A. 建立：0:00–0:16.161

无线电从黑暗中亮起，小鑫一边封三号门一边回应。他的承诺与行动一致，观众站在他这一边。

### B. 复杂化：0:16.161–0:31.382

四个频道逐渐具体：缺水、火灾、路线、抵达时间。小鑫用车灯、路标和奔跑的照片证明自己没有消失，却始终不给确切时间。

### C. 收紧：0:31.382–0:39.404

四栋楼、一辆车、一条隧道，资源冲突第一次变成不可回避的物理事实。五枚倒计时灯开始熄灭，尸潮逼近。

### D. 反转与峰值：0:39.404–0:55.879

“马上就走”仍配合奔跑，但镜头随后从他的嘴移到脚：脚已停在岔路口。四路求救把他的脸和手包围，倒数结束时镜头升高，他在三条路线中央变得很小。

### E. 余波：0:55.879–1:03.121

无线电里的人继续呼叫。小鑫离开画面，或者无线电从他手里滑下；答案保持模糊。最后四枚频道灯同时熄灭，声音切断，黑场至少保留 8–12 帧。

## 4. MiniMax H3 制作策略

- 成片拆成 13 个主镜头，实际时长 3.552–6.874 秒，全部低于 15 秒上限。
- 每个镜头先做一张确定构图、身份、灯光和道具的起始帧，再用图生视频驱动动作。
- S02、S08、S12、S13 同时准备结束帧，使用首尾帧模式控制“门关闭、尸潮逼近、镜头升高、频道熄灭”四个关键结果。
- H3 可按目标时长生成 4–15 秒；若使用只提供 6/10 秒档位的 Hailuo API，则 S02、S06 用 10 秒，其余用 6 秒，后期按节拍裁短。
- 每条视频提示词只写“人物动作 + 镜头运动”。服装、场景、色彩和构图由起始帧与 `DESIGN.md` 负责，避免文字与图像互相冲突。
- 生成视频的音轨全部弃用。最终把 `sources/小鑫_多频道求救_音频.mp3` 作为唯一主音轨重新封装。

## 5. 单帧资产策略

### 场景与人物分开制作

1. 用户先用 Midjourney 生成无人物场景，锁定建筑、空间、灯光、雾、雨和整体美学。
2. 用户把选中的场景原图交给 Codex。
3. Codex 使用场景原图和 `references/` 下三张小鑫参考图，制作带人物的剧情关键帧和配套特写。
4. 通过的关键帧再交给 MiniMax H3 动起来。

这样 Midjourney 不需要承担真人身份一致性，人物也不会反过来破坏已经选好的场景风格。

### 景别必须成组，而不是平均分配

MV 采用“剧情镜头交代处境，特写镜头揭示心理”的配对结构：

- S02 封门全身动作 → S03 脸部安抚特写
- S04 四频道车内过肩 → S05 水与火的环境中景
- S06 奔跑剧情镜头 → S07 地图与手的插入特写
- S08 尸潮隧道大远景 → S09 小鑫奔跑全身/中景
- S10 嘴与靴子的核心特写 → S11 脸和手的情绪近景 → S12 岔路俯拍大全景
- S13 无线电超近景回收母题

因此成片既有空间与行动，也有表演和细节。不是“每句歌词一个特写”，也不是“一组空景讲完整故事”。

### 必需资产：13 张起始帧

每个 S 镜头一张，决定整个镜头 90% 的视觉信息。先做四张校准图：

1. S01：无线电与手部微距，验证末日质感和道具
2. S05：水与火同框，验证世界观和色彩冲突
3. S10：脸到脚的岔路构图，验证主叙事反讽
4. S13：失联无线电，验证结尾质感

四张一致后，再出剩余 9 张。

### 可选资产：4 张结束帧

- S02_end：三号门完全封闭
- S08_end：尸潮轮廓推进到隧道中段
- S12_end：俯拍下小鑫停在三条路线正中央
- S13_end：四枚绿色频道灯全部熄灭

总量为 13 张必需图，17 张完整控制版。不要一次性批量生成 17 张；先锁定校准图，能显著减少人物和服装漂移造成的返工。

## 6. 制作阶段

### 阶段 1：风格校准

- 用户在 Midjourney 先生成 E03、E09、E16/E17、E18 四组无人物场景
- 选择同一套 Style Reference 下最统一的场景原图
- 把选中的原图交给 Codex，再制作 S01、S05、S10、S13 人物/道具校准关键帧
- 检查脸、耳饰、发型、服装、绷带、无线电和场景色彩是否融合

### 阶段 2：关键帧补齐

- 根据已选 Midjourney 空景完成 13 张带人物/道具的起始帧
- 完成 4 张必要结束帧
- 做连续性检查：奔跑方向、手持无线电、绷带侧、伤痕位置、夜色一致

### 阶段 3：MiniMax 小样

- 先生成 S02、S10、S13 三个风险镜头
- S02 检查机械门与手部；S10 检查镜头从脸到脚；S13 检查无线电灯按顺序熄灭
- 风险镜头通过后再批量生成其余镜头

### 阶段 4：粗剪

- 所有镜头按 `01_歌词与剪辑时间轴_V0.1.md` 入轨
- 在节拍前 2 帧尝试切点，再按观感微调
- 只保留原始歌曲；模型音频静音
- 添加 Radio Intro/Outro 的轻微噪波、频道串扰和尾部硬切

### 阶段 5：精修与交付

- 镜头色彩统一、去闪烁、必要时补帧或轻微稳像
- 字幕后期添加，绝不让生成模型在画面中直接写歌词
- 输出 16:9 主版；需要时从中心安全区另裁 9:16 版本

## 7. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 人脸和服装漂移 | 三张人物参考共同锁定；先做四张校准图；每镜复用同一身份描述 |
| 无线电、手指变形 | 尽量用固定手势；关键手部用首尾帧；必要时裁到手部动作前后 |
| 同一镜头动作过多 | 一个生成片段只承载一个主要动作；复杂信息通过镜头内移焦而非多次转场 |
| 路牌和 UI 乱码 | 生成阶段只用色块、箭头和灯；具体字在后期叠加 |
| 尸潮抢走人物主题 | 只用轮廓、影子和远景；不出现正面啃咬或血腥特写 |
| 13 段素材风格不统一 | `DESIGN.md` 为唯一视觉真值；统一冷蓝基底、琥珀行动光和红色警报 |
| 15 秒内叙事拥挤 | 实际每镜 3.5–6.9 秒；不要求模型在单段内完成多个场景跳转 |

## 8. 验收标准

- 前 3 秒能看懂“无线电求救 + 主角必须回应”的钩子
- 即使关闭字幕，也能从水、火、车辆、隧道和岔路理解资源冲突
- “Hold on，马上就走”之后，画面必须明确完成“嘴在答应、脚已停住”的反讽
- 主角从头到尾是同一个人、同一套服装、同一晚、同一无线电
- 高潮不是最大规模打斗，而是最清晰的选择困境
- 结尾在无线电熄灭后立即硬切黑，不补解释性镜头
