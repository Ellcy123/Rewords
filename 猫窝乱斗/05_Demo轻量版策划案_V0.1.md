## 1. 玩家一句话能懂的玩法

**买猫和用品，塞进方形猫窝；用品放对位置，猫就变强，帮你打过下一关。**

“舒服”通过表情、爱心和魔法联动表现，暂不单列舒适度评分。玩家不需要理解猫为何能释放魔法。

本项目把易上手作为 IAA 产品的设计目标，但不能据此断言所有 IAA 都只需要低难度，或当前包装已验证吸量。

## 2. 这版保留什么、减掉什么

| 范围 | 首版处理 | 理由 |
| --- | --- | --- |
| 不同猫的体型与占格 | 保留 | 一眼能懂的拼装趣味 |
| 旋转、切换姿势 | 保留；每种猫只配置少量预设姿势 | 不做连续挤压或复杂操作 |
| 猫与用品邻近联动 | 保留 | 摆对位置马上见效 |
| 商店、金币、购买扩容 | 保留 | 每轮有明确补强选择 |
| 轻量自动战斗、每关限时 | 保留；建议只战斗计时 | 布置允许思考，战斗控制节奏 |
| 10 种猫、20 种用品 | 保留最终 Demo 内容量，分批进入商品池 | 不让新手一次读完 30 个条目 |
| 广告金币、复活 | 保留两种，自愿触发；Demo 使用模拟入口 | 先验证体验 |
| 职业、转职、PvP、排位 | 暂不做 | 减少学习与制作负担 |
| 体力、蓝量、命中、暴击、毒、反伤等 | 暂不做 | 玩家先理解攻击与防护 |
| 配方合成、用品之间的触发链 | 暂不做 | 不要求背配方，不做多层事件连锁 |
| 猫之间互相讨厌、复杂关系网 | 延后 | 前期避免摆错就受罚；保留用品喜好 |
| 猫咪永久养成、升星、进化缩小 | 延后 | 先靠局内买入、搭配与扩容体现变强；成长方向不删除 |
| 舒适度独立数值 | 不加入当前版本 | 避免出现第二套难理解的通关条件 |

“减法”优先减少规则种类，而不是把已约定的 10 猫、20 用品悄悄缩成最终只有 3 猫、6 用品。

## 3. 一局怎么进行

首版建议一局 6 关：

领取初始猫与金币 → 商店选购 → 摆放／旋转／换姿势 → 开战 → 自动战斗 → 胜利拿金币 → 保留阵容进入下一关 → 第 6 关获胜后本局完成。

- 轮与关在本 Demo 中一一对应；一局包含 6 关。
- 失败先进入重试选择，不立即清除阵容。玩家可以调整摆放后免费重试本关。
- 每次开战双方满血，战斗中临时护盾重置。猫、用品、金币与扩容跨关保留。
- 新开一局重置局内资源，保留已完成的新手教学标记和设置；退出后可继续未完成局。
- 原型以短局为目标，具体总时长由试玩测量，不把预估分钟数当作结果。

## 4. 摆放与姿势

### 方形猫窝

起始建议 4×4，金币购买整档扩容为 5×5、6×6，最大 6×6。一次购买完整新增区域，始终保持方形；不设置逐格缺口。价格见经济取样。

### 操作

- 猫和用品拖入格子，自动吸附；有效位置亮起，冲突位置标红。
- 点击猫显示两个独立按钮：旋转、换姿势。只存在一种基础姿势的猫不显示换姿势按钮；首批必须包含可换姿势的猫。
- 旋转与换姿势不消耗金币、不占战斗次数；不要求按住一种输入再同时按另一种。
- 切换后放不下则保留原状态，显示轮廓预览，不挤走其他物品。
- 不同猫独立配置占格和姿势，不强制都是 4 格，也不把等面积当永久要求。首版具体形状后续逐只填写。
- 进化获得更小姿势不进入此次 Demo。

### 暂存与出售

未摆入猫窝的已购物品进入清楚标识的待摆区，不参加战斗。开战前至少有一只猫在窝内；有待摆内容时提示一次但允许继续。允许随时在准备阶段出售，减少买错后的挫败。

## 5. 猫自身能力与联动

2026-09-25 补充共识：每种猫先有自己的加成，再有连接效果。猫的差异不能只靠体型、基础攻击和用品喜好。每种猫分别配置“自身能力”和“连接条件与收益”，参考背包乱斗的位置联动结构；细化以 06 第 4 节为准。首批建议每猫各一条，自身能力无需用品也生效；具体技能尚待配置。


首版建议：用品与猫上下左右贴边即为邻近，斜角不算。同一用品接触一只猫的多个格子，只计算一次。

- 每只猫只显示一种主要用品喜好，例如玩具、食物或寝具；具体分类与归属另配。
- 每件用品只有一个主要效果，只影响邻近、符合喜好的猫；一件用品可以服务多只符合条件的猫。
- 同名用品对同一只猫不叠加；不同用品可以同时生效，同类数值相加，不做乘法放大。
- 不额外设置“选择哪两件生效”的操作，玩家只需考虑邻近与喜好；过强组合优先通过占格、价格和数值调整。
- 拖动过程中实时显示将连接谁；落位后以短连线、满足表情和“攻击提高”等短提示确认。
- 无效摆放不施加额外负面效果，只是没得到加成。

首版数值效果只用两类：攻击加成、开场护盾。先不加入触发次数计数、资源转换和多段连锁。

这比背包乱斗的完整作用格、职业资源与事件链简单。未来要增加复杂度时，先验证当前组合是否已被玩家理解。

## 6. 自动战斗与胜负

### 基础方案

- 我方全体猫共用一条队伍生命，对面一个敌方目标。猫按各自固定间隔造成伤害。
- 猫自身能力与用品联动改变攻击或贡献开场护盾；所有有效开场护盾加到队伍护盾条，先吸收敌方普通伤害。
- 不给每只猫独立血条，不做寻路、选目标、单猫死亡和战斗中手动释放技能。
- 战斗时不允许购买、出售或改变摆放，技能表现通过猫的动作与魔法效果完成。
- 敌方生命归零获胜；我方生命归零失败；同时归零暂按失败，后续若改必须统一提示与结算。

### 限时方案（新建议）

每关战斗上限暂取 25 秒；准备阶段不限时。敌方未被击败即超时失败；不叠加原作疲劳伤害。界面明确写“战斗限时”，避免误导为整关含商店倒计时。

切后台、暂停以及模拟广告期间停止游戏计时。复活见第 8 节。

### 看得懂的反馈

开战前只显示生命、预计基础输出和当前联动数，不堆复杂属性。战斗中让产生效果的猫与用品短暂高亮。

失败建议基于真实情况：有闲置用品时提示尝试贴近猫；有未激活喜好时指出对象；没有依据时仅说明“时间耗尽”或“生命耗尽”，不伪造最优解。

## 7. 商店与金币

### 简化商店

每轮先给 3 件商品：前两关固定教学候选，之后逐步扩大商品池。普通候选维持“至少一只猫和一件当前阵容可用用品”的供给约束；达到内容边界时允许用品替补。

- 刷新一次替换所有未购买商品，不加入锁定、折扣、稀有度抽卡界面。
- 购买后槽位留空，刷新或进入下一关才补货，避免连续无限补货改变经济节奏。
- 每轮首次刷新免费，后续每次 1 金币。失败重试不重置免费次数、不重抽商品、不重新发收入。
- 刷到的新品不会强制优于旧品；选择依据优先是当前空间和搭配。
- 商店金币不足时不自动播放广告，不强弹广告确认。

### 第一轮可调参数（仅调试起点）

| 参数 | 初始建议 |
| --- | --- |
| 开局 | 1 只基础猫＋10 金币 |
| 第 1–5 关首次通关收入 | 每关 6 金币 |
| 猫价格 | 4–8 金币 |
| 用品价格 | 2–4 金币 |
| 扩容 4×4→5×5 | 8 金币 |
| 扩容 5×5→6×6 | 12 金币 |
| 出售 | 实际买入价一半向下取整；初始赠猫售价 0 |

首批敌人和商品必须支持不看广告通关；这是设计目标，尚未测试。不得通过反复重打已获胜关卡重复领取本局金币。

## 8. 广告与失败容错

沿用已确认的金币、复活两种奖励，不增加广告独占猫、强制插屏或广告抽奖。

### 金币奖励

准备阶段自愿观看，暂定 +4 金币，每关最多 1 次。标出实际收益；失败重试不刷新广告次数。模拟成功后只发一次奖励，取消或失败不发奖。

### 复活奖励

失败后自愿观看，获得并立即使用 1 次本关复活；不跨关囤积。暂定每关 1 次。

为减少状态分支，复活采用“保留阵容重开本场，并获得本次最大生命 +20%”：双方重新满血、计时重置为 25 秒、临时护盾重新计算。额外生命仅本次有效，不跨关累计。需要测试其价值，不能宣称必定通关。

同时保留“返回布置，免费重试”入口。免费重试没有额外生命，可调整阵容，但不重发收入和免费刷新次数。放弃本局则回开局。

真实平台广告 SDK、展示频控和审核要求待发行平台确定后设计；当前不承诺任何平台合规结论。

## 9. 内容与教学节奏

10 猫、20 用品是完整 Demo 内容池，不要求玩家一局见全，也不要求每关引入新系统。

| 阶段 | 首次学习重点 |
| --- | --- |
| 第 1 关 | 买一件适配用品，贴到猫旁边，看联动后开战 |
| 第 2 关 | 加入体型不同的猫，学习旋转；提供合适空位 |
| 第 3 关 | 学习一只猫的换姿势，解决具体空隙问题 |
| 第 4 关 | 体验金币扩容与购买用品的取舍；扩容不是免费赠送 |
| 第 5–6 关 | 使用已学规则补强，适量提高敌人数值，不突加新系统 |

第一轮制作使用 3 猫、6 用品验证整个循环；成立后补齐 10 猫、20 用品。猫和用品的名字、形状、属性与完整搭配表另写，不用占位名单冒充完成设计。

内容差异来自体型、攻击节奏、用品喜好、加成与价格的组合，不以 30 种独立新规则撑内容量。如果出现多个条目仅换皮、没有选择价值，应调整内容配置而非继续加机制。

## 10. 美术与操作表现

题材与风格更新（2026-09-25，用户确认）：猫保护小主人，对抗梦魇；整体带点怪诞，不采用此前助手提出的童话风方向。猫、敌人和场景应统一探索这一气质，具体造型与配色尚未定稿。共识与视觉建议见 02。

- 纯 2D；猫的轮廓应能解释占格，避免大量透明边缘让玩家误判。
- 姿势变化是有明确轮廓的预设图，不做 3D 或实时柔体。
- 首版先制作一只猫的两姿势、一个用品、一套盒子与联动表现，确定品质与格子可读性，再批量扩展。
- 制作工具沿用 Unity 6+、Midjourney＋image2；首版界面暂按竖屏触控设计，具体发行平台未定。
- 猫落位、联动激活、伤害与胜利分别有短反馈，避免满屏粒子盖住格子。

## 11. 先验证哪些体验

这是一份试玩检查目标，不是已完成测试：

1. 第一次接触的人能否看提示完成买入、摆放、开战。
2. 玩家能否说出自己摆出的一个组合，以及增强了什么。
3. 第一次失败后，是否知道至少一个能尝试的调整。
4. 25 秒战斗是否过长／过短；准备时间是在思考还是在找按钮。
5. 不看广告是否能完成正常前期流程，免费失败重试是否会形成死局。
6. 是否出现永远买最小猫、某一用品必选、姿势永远不需要切换等问题。

程序验证由项目指定 GPT-6 Luna / xhigh 子代理，通过 Unity CLI 执行适合的检查；当前只写策划，尚未执行游戏测试。
