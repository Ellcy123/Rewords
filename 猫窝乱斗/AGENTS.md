# 猫窝乱斗项目约定

本文件仅适用于 `猫窝乱斗/` 及其子目录，不推广到仓库中的其他项目。继续遵守仓库根目录的协作与测试规则。

## 透明素材默认使用 Canva 抠图

2026-09-27 用户确认：本项目所需尺寸在 800 像素以内的图直接使用 Canva 工具抠图，不再为抠图制作绿幕背景。用户预计猫窝乱斗大部分独立素材可采用此流程；这不代表所有素材尺寸已确定。

- 按**最终所需导出图的长边不超过 800 px（含 800）**执行；不是要求生成原图必须小于 800，也不把所有素材强制降到 800。
- 需要透明底的猫、怪物、用品、图标及独立 UI 素材，满足上述尺寸时默认使用 Canva 插件 `remove_background`，不再逐项询问工具选择。
- 不再为了色键抠图而要求绿幕、纯绿色背景或给主体配色让路；出图背景保持简洁、主体边界可辨，按正常美术需求生成后交给 Canva 抠图。
- 满底场景背景、无需透明的图片不必抠图；本约定不改变“背景由 Midjourney 生成、其他图像素材由 Codex 内置图像生成”的现有分工。
- 超过 800 px 的素材另选能取得足够分辨率的流程，不放大 800 px 结果冒充高清；Canva 授权失效或出现付费阻断时明确报告，不自动购买或启动订阅试用。
- 原图保留，抠图另存带真实 alpha 通道的 PNG；用于 Unity 前按实际显示尺寸查看边缘、孔洞与主体完整性，测试仍遵守根目录的 Luna/xhigh 规则。

流程与实测限制见 [美术工作区](美术/README.md#透明素材抠图约定仅限本项目)。

2026-09-28 用户确认将合适的布局 skill 放入项目。设计、修改或审查本项目 UI 布局时，读取 [game-ui-frontend](../.codex/skills/game-ui-frontend/SKILL.md)，优先遵循其中“猫窝乱斗项目适用边界”。当前采用 Unity Canvas 程序 UI；浏览器规则不构成更换技术栈的要求。

## UI 试制必须沿用原定画风

2026-09-29 用户再次明确“要用原来的”：根据程序布局制作对应尺寸 UI 时，先读取美术规范及 B 版纸片拼贴原提示词，沿用已选风格，只补充当前尺寸、切片、文字安全区与状态适配要求。程序界面的临时颜色不构成重新选择画风的依据。后续用户明确“就按照这个制作所有的UI，注意先生成一张示意图，考虑好配色”，已扩展授权到整套UI；必须先制作配色示意图，继续保持程序布局、独立文字和原B风格。

## 当前 UX 讨论载体

2026-09-29 用户否定此前 Unity UI 的整体体验，并要求“先做一个网页版的示意，本地纯前端的就行，然后我们一起调整一下”。当前在 `原型/UX网页示意/` 制作第一关可交互草案供共同调整，不据此擅自替换 Unity 技术栈。功能测试通过不等于交互设计或视觉质量获认可；网页自身也需接受用户评审。

2026-09-29 本轮用户进一步确认：网页以9:16为基准；准备页参考已讨论的背包手游组织方式，战斗时不显示格子；要求准备与战斗一起展示。此项是界面表达要求，不改变猫/用品的占格和邻接规则，也不等于认可草案其余细节。

2026-09-29 用户纠正准备流程：购买之后从待放区拖动入窝，面条也不默认在窝内，所有角色/用品由玩家后放入。当前网页实现保留初始赠送面条但放在待放区；不能把旧策划的自动预摆基线再次当成当前要求。Unity尚未同步。

2026-09-29 用户指出“返回布置应该不能返回了”：当前网页已移除战斗/首夜胜利后的同夜返回入口。胜利应结算后推进下一夜，不可回到已胜利夜晚继续摆放；单夜示意止于结算，通过画幅外重置重新演示。此轮未讨论失败重试规则，不能据此删除策划中的失败调整重试。

2026-09-30 用户反馈“C好像好一些，但是猫窝去哪了”：以C作为本轮细化方向，尚非最终定稿。战斗隐藏格子仅指隐藏内部格线，必须保留可辨认的方形猫窝本体、底面与外沿；不能把猫窝淡化为透明地垫，也不应把方形摆放区域压扁。角色和用品继续对应准备阶段摆好的相对位置。

2026-09-30 用户进一步要求猫窝有真实窝体的质感，并因战斗不操作而缩小占地。当前C改用灰蓝布艺包边、米色软垫的空猫窝图，战斗窝体缩小，准备页保持大的摆放区域；v7纸箱外沿仅为已被纠正的中间稿，不再当成用户选定外观。沿用手绘画风，不把“真实窝体质感”解释为整套UI改成写实照片。

2026-09-30 用户认可布艺猫窝，并明确“C方案就好，按照这个继续优化”。当前以C作为选定布局继续；不再把A当成默认推荐，不据此宣称所有UI已验收。下一步重点为血条下方攻击预告与各处文字的清晰度：保留原B纸感配色和布艺猫窝，整理信息层级并实际查看窄屏效果。

2026-10-01 用户纠正战斗右上角应为加速，而非暂停。网页HUD已将该入口改为战斗倍速；先采用可来回切换的×1/×2作为本轮实现选择。倍速作用于敌我攻击、战斗倒计时、攻击预告及对应动作，不能只加快动画。切后台停止逻辑时间的保护保留；本次不表示删除正式Unity中的系统暂停规则。

2026-10-01 用户要求继续设计主界面和爬楼关卡，并授权在现有网页产出交互示意。网页新增小屋、猫咪培养、用品图鉴、签到/任务/模拟补给和楼层预览，第一层连接已有准备战斗，后续战斗暂未接入。以上局外数值、解锁条件和六层章节结构仍是助手交互草案，不等于用户确认全部系统规格；此前 Demo 延后永久养成的范围不用于阻止本次网页探索，也不自动扩大 Unity 开发范围。
