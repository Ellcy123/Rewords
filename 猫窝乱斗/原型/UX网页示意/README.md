## 本轮设计
- 每个游戏画幅固定390×693⅓（9:16）；桌面两页并排，900px以下通过页外标签切换。窄屏按宽度缩放预览，不改变设计画幅。页外标题、注释不属于游戏内容，游戏画幅内部不滚动。
- 准备页：上方关卡与开战、商品与金币；下方330px方形猫窝；底部固定待放区，容纳初始面条与购入用品。购买后不会移动猫窝或待放区。第一关仅一件商品，没有假商品或空位按钮。
- 2026-09-29用户纠正：统一先购买进待放区，再拖放。取消商店直接拖入购买与点格落位；猫窝初始为空，赠送面条也在待放区，由玩家拖入。猫和玩具均可在窝内挪动或拖回待放区。越界/重叠/取消拖动恢复原处，不丢物品、不重复扣款。绿色轮廓表示合法，金色表示贴边联动。窝内无猫时不可开战。
- 战斗页：复用既有卧室与第一关Boss资产；上方梦魇、下方猫与用品。没有网格DOM，也没有可拖放操作，按准备页相对坐标展示已入窝的阵容，动态计算面条与用品邻接，不再假定面条固定在第二行，隐藏商店。
- 左右共享阵容。右侧“播放战斗示意”只为原型评审；准备页“开始守梦”同样能开战。约10–16秒的普通攻击示意，带出招/受击/血量/暂停与结果，战斗数值不是正式平衡实现。首夜胜利后停留结算，不可返回同一夜布置或重打；完整游戏应进入下一夜。此示意未实现后续关卡，重做演示使用画幅外的“重置这版示意”。

## 拖放失败修正（2026-09-29）
用户报告“拖入不进去”，当前IAB页面确实留下“已取消拖动，物品保留在原处”，不是此前固定落点测试可以排除的问题。v4调整：阻止浏览器默认图片/文字拖拽；使用窗口级Pointer移动/松手监听，失去捕获本身不再取消；指针在猫窝内时把完整占格贴边吸附，仍拒绝重叠；绿色提示只标出当前实际落位格。旧版中心点计算会让面条拖到第一/第四列时越界，是代码可确定的另一处问题。导致用户此次取消的具体事件来源需以复现结果为准。

验证边界：Luna子代理可用的浏览器工具无法访问主任务当前IAB会话（显示browser unavailable/session已占用）；因此v4使用独立Chrome做鼠标/触摸事件复测。主代理读取了用户IAB现存的取消提示并刷新修复，但不把独立Chrome通过表述成用户当前IAB复现通过。

v4 Luna复测结果：鼠标图片起拖首列通过；390宽CDP触摸从图片起拖首列、从文字起拖第四列均通过，轮廓与落位一致（索引0/1）。主动releasePointerCapture后hasPointerCapture由true变false，后续move到棋盘DIV仍能通过窗口监听落位；该例Chrome未派发lostpointercapture，不冒充该事件已被模拟。触摸实例正常pointerup后会出现lostpointercapture，未出现pointercancel/dragstart。见 `review/round3/v4-touch-edge-report.json`、`v4-first-column.json`。用户原IAB取消来源尚未单独复现。
