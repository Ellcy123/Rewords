# 首批通用纸片 UI 正式资产 V0.1

日期：2026-09-28。状态：V2 静态审查与 Unity 第五轮显示验收均通过。

## 权威依据

- 组件种类和尺寸来自当前 Unity 实际界面：信息面板、操作按钮、棋盘格、商品框。
- B3 样稿只负责纸片拼贴的画风提示：切角、局部折角、错位衬纸、简练墨线和克制的手裁感；样稿里的图标、文字、排版和渐变不是正式外观依据。
- 所有文字、数字、价格、状态说明和物品图标由 Unity 叠加，不画进底图。

## 统一造型

- 四角采用同一家族的 10%–12% 切角；左右轻微不对称，但同类组件之间保持一致。
- 深墨褐轮廓，线宽约为短边的 3%–4%；不能有塑料高光、软糖圆角或空气喷枪渐变。
- 前层与衬纸之间用窄小实色错位表现按压和层次，不依赖投影模糊。
- 内容安全区至少保留四周 14%；纹理只允许非常稀疏的局部色差，不能影响中文可读性。
- 透明 PNG，画布边缘留至少 4 px；全透明像素 RGB 清零，无杂色光晕。

## Unity 使用

- 面板、按钮和商品框按九宫格方式缩放；格子保持等宽等高。
- 按钮状态由 `Selectable` 切换对应 Sprite；选中、连接和非法提示使用独立格子底图。
- 角色和用品整图跨越真实占格显示，格子仍负责点击、拖动和连接反馈，不能在每一格重复铺角色图。

## 审查

1. 缩到 Unity 实际按钮高 30–54 px、格子边长 68–105 px 后，切角和状态仍清楚。
2. 普通、按下、不可用不能只靠颜色区分。
3. 文字安全区平静，轮廓和衬纸不压字。
4. 与正式角色、用品和卧室背景同屏时，UI 层级清楚但不抢主体。
5. 同一批资产累计三次审查失败后停止重做并记录最佳版本。

## 迭代记录

- V1：组件和尺寸齐全，但禁用态只靠颜色区分；5 张横向组件透明边距只有 2–3 px。审查失败 1 次。
- V2：禁用态加入三道内收裁痕；全部组件四边透明留白至少 4 px，全透明像素 RGB 清零。独立静态复审 PASS。
- Unity 首轮：资产本身正常导入；真实界面需要给标题、状态、操作带、选择说明和消息增加稳定纸片底，并在商店框中实际显示用品图。
- Unity 第二轮：补齐承载板和商品图，但九宫格竖向边框大于实际控件高度，面板被挤成白条。
- Unity 第三轮：修正九宫格后面板恢复完整，正式资源、跨格显示、商品图、自动测试和构建均正常；实际 540×942 Player 中标题、状态、提示、选择和底部消息仍有裁切、贴边和边线干扰。累计三次显示审查失败，当时按约定 STOP 并保留第三轮。
- 2026-09-28 用户确认“如果是 Unity 的问题继续调整”，明确重新打开该接入项。第四轮只修改 Unity：文字垂直溢出改为 Overflow，扩大并内收标题/状态文字框；`ui_panel` 只用于高面板，提示、操作、选择、消息和页脚改用适合细条高度的 `ui_shop_normal` 九宫格。正式 PNG 外观不重画。
- Unity 第四轮：提示、操作、选择和商品区明显改善，床沿不再穿过操作按钮；仍因标题框 preferredHeight 32px 大于实际 28px、顶部面板可见内区不足，造成标题/状态挤压；消息与页脚位置偏低。第五轮将 Header 也改为细条九宫格，标题降到20px并分离状态行，消息与页脚整体上移。
- Unity 第五轮：PASS。实际 540×942 macOS Player 中标题、状态、敌人、提示、操作按钮、选择说明和 Footer 均完整落在纸片区域；提示与操作条连续遮住床沿高细节。EditMode 17/17、PlayMode 5/5、StandaloneOSX 临时构建通过。旧存档当帧消息字符串为空，非空消息由 `PrimaryTextFitsItsPaperPanelsAtReferenceLayout` 覆盖。
