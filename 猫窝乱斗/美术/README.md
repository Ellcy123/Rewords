## 透明素材抠图约定（仅限本项目）

**2026-09-27 用户确认：最终所需导出长边不超过 800 px（含 800）的透明素材，默认直接使用 Canva 插件抠图，不再为抠图生成绿幕背景。仅适用于猫窝乱斗，不作为其他项目的通用规则。** 用户预计本项目大部分独立素材可采用此方式；各资产实际尺寸仍在需求中填写。

- 保持现有出图工具分工；需要透明的独立素材按正常美术要求生成，背景简洁、轮廓清楚即可，不写绿幕／纯绿背景／色键要求，也不限制主体使用绿色。
- 上传原图到 Canva → 调用 `remove_background` → 获取透明 PNG → 按最终用途缩小、保存到导出目录。保留原图，不把无需透明的满底背景也送去抠图。
- 本次实测已成功处理火箭和长毛犬，无升级阻断；当前可确认取得的是 Canva 媒体页实际加载的 **800×800、带 alpha 的 screen 资源**。插件仅直接给出 200×200 缩略图；资产元数据虽为 1254×1254，原尺寸下载尚未打通。不能把缩略图、放大图或元数据当成高清文件，也不据此承诺免费不限次。
- 取图时优先正常下载；若使用页面图片资源，只保存页面实际提供的地址，不猜测或修改签名 URL 的尺寸参数。超过 800 px 的需求另行选择可取得足够分辨率的方式。
- 导出前检查实际尺寸、透明通道及深浅背景上的边缘，必要时修正明显白边、杂草残留或主体缺失；账号授权／付费阻断要如实说明，不自动购买。

本轮已验证文件：[火箭 800 px](../../output/mac-cutout-20260927/canva-easy-screen-800.png)、[长毛犬 800 px](../../output/mac-cutout-20260927/canva-hard-screen-800.png)。项目执行入口：[AGENTS.md](../AGENTS.md)。

## 当前制作原则

- 临时资产必须看得清占格、猫的身份、连接与战斗反馈；不作为正式画风依据。
- 用户已授权首轮3个方向的风格试稿，由独立worker生成对应提示词和图片；不扩成全套正式资产，Unity暂时继续用占位资源。
- 每次正式出图或修图前先有明确的需求文档。相同规格的批量小资产可以共用一份需求，但必须逐项列出资产 ID 与差异。
- 调整同一资产时更新原需求的版本和改动说明，不只在聊天里留口头修改。
- 临时原生图形不需要每个色块一份文档，统一遵循临时资源规格；如果临时资产也调用生成工具，同样先写对应出图需求。

## 正式美术集中阶段

1. 先收敛竖屏布局与美术需求，再用少量样稿选风格。
2. 背景由 Midjourney 出图并迭代构图和游戏区域留白；其他图像素材由 Codex 内置图像生成直出。保留原始结果与实际提示词；具体导出、分层与导入按资产需求另行安排。
3. UI、小用品等继承通用画风，按面板、图标、用品分支补充规格；UI 提示词先出小样验证，避免把角色的五官、夸张比例等描述直接套到界面。具体色板另行收敛，不写入无配色画风段。
4. 先完成一个背景、一猫两姿势、一个敌人、一个用品和一组 UI 样板，放到实际游戏尺寸下看整体，再扩展首批 3 猫 6 用品与前三关。
5. 同一套提示词不能保证自动一致，保留参考图和对比修正步骤。UI 文字由 Unity 排版，按钮与面板独立制作，不把整张生成图直接当可交互 UI。
6. 最后按实际返工量估算剩余 10 猫 20 用品的批量工作，不提前把未定风格画满。
