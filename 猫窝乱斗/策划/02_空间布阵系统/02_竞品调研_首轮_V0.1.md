# 空间布阵系统 · 首轮竞品调研 V0.1

调研日期：2026-10-02。用途：第二系统细化前的资料依据。本轮为网页资料调研，没有亲自试玩；旧拆解仅代表文中版本，不冒充2026年现行规则。以下区分官方说明、作者体验、玩家反馈和本项目推论。

## 1. 先看与本项目有关的结论

1. 空间类玩法通常同时包含“装得下”和“摆得有效”两种选择。我们已有猫与用品联动，不能只显示剩余格数，还要让玩家看到谁获得了效果。
2. 不同产品的广告扩容、随机格块、合成腾位置并非一套通用规则。本项目先承接方形猫窝、整档扩容和独立待放区，不因为竞品流行合成就增加猫咪合成。
3. 部分国内产品把格子作为广告资源；玩家也会抱怨空间与广告捆绑。它说明存在体验风险，不能据此推导整体留存或收入。本项目建议正常局内金币能够支持必要扩容，具体节奏交经济配置验证。
4. 拖放失误不应造成购买物丢失；放置、联动预览、进入战斗应有明确阶段。下文官方更新中出现过放回刷新栏、移动卡住等问题，值得提前明确我们的交互规则。

这些是助手判断，不是用户已确认的新需求。

## 2. 国内主要样本

### 2.1 花园特攻队：有限空间、不同占格与邻接效果

- 平台及资料：国内小游戏；GameRes收录林彦丞2024-05-10体验拆解，作者将当时版本归为纯IAA。
- 资料可支持：初始3×3；波间提供装备或扩展格；装备有不同尺寸，入包才生效；存在邻接增益；同类同级可合成。该版本刷新会替换未放入的候选物。
- 借鉴：放置合法性与邻接效果分别反馈，准备后明确点击开战。
- 不照搬：刷新清掉未放候选物，不能变成清掉我们已经购买的待放物；随机扩展格不替换已选方形猫窝方向。
- 未核实：当前版本、手机旋转手势、具体扩容保底。原作者对保底的猜测不当作事实。
- 来源：[产品简析](https://www.gameres.com/905847.html)。

### 2.2 吃不到我呀：空间供给与高阶单位的压力

- 平台及资料：微信小游戏；罗斯基2024-07-03体验文章，17173转载，称当时为纯广告变现。
- 资料可支持：开战前和每轮结束后整理；准备页有常驻获取格子的广告入口；指定高阶水果组合可形成更高阶水果。
- 借鉴：准备阶段集中处理空间问题；大占格单位应有足够明确的价值，不能只是更难塞。
- 不照搬：把基本空间需求变成反复观看广告的前提；我们还没有决定做合成，不移植杂交链。
- 未核实：当前商业化结构、旋转操作、待放区容量。玩家对占格和广告的评价仅作风险线索。
- 来源：[罗斯基体验拆解](https://news.17173.com/content/07032024/093904631.shtml)、[TapTap玩家反馈](https://www.taptap.cn/app/713690/review)。

### 2.3 保卫向日葵：格子效果可见，以及拖动与阶段切换

- 平台及资料：国内手游；App Store有内购，官方公告也提及广告格子，作为混合变现对照。主要依据2026-02-12更新公告。
- 官方可支持：增益格子增加彩色标识；修复放置地块后格子减少、植物或精灵回到刷新栏、跳波次移动广告格子或植物时卡住等异常。
- 借鉴：占格之外的效果要有独立标识；拖动中切换阶段、广告返回后恢复对象归属，需要明确处理。
- 不照搬：公告涉及战斗中的摆放，我们仍采用准备阶段调整、战斗固定阵容。
- 未核实：全部地块规则和当前触控手势，不能从一篇修复公告推断完整系统。
- 来源：[官方更新公告](https://www.taptap.cn/moment/770694646136309758)、[官方商店页](https://apps.apple.com/cn/app/保卫向日葵/id6737974680)。

### 2.4 口袋宠物猪：整理与储物的分工

- 平台及资料：国内手游；官方商店标注内购，TapTap官方版本记录包含视频广告优化，按含广告与内购的产品对照，不称纯IAA。
- 官方可支持：背包合成结合塔防和随机技能；2024-08-09版本记录新增背包储物格，并设通关条件。
- 借鉴：作战空间与临时存放空间可以分开；需明确什么会进入战斗，什么只是已持有。
- 不照搬：我们已确认所有购买物先进入待放区，这个基础流程不应等十关后才解锁。
- 未核实：该储物格与我们待放区是否完全同义、数量和开战后保存规则；玩家提出旋转建议不证明现行版本仍不支持旋转。
- 来源：[官方商店说明与版本历史](https://apps.apple.com/cn/app/口袋宠物猪/id6503722889)、[TapTap官方信息](https://www.taptap.cn/app/710964/all-info)、[玩家反馈](https://www.taptap.cn/app/710964/review)。

### 2.5 背包战争（TapTap app/710112）：仅作体验问题样本

- 身份边界：此处是国内手游条目，不是Steam的《背包乱斗：福西法的宝藏》。未核实当前收入结构，不贴纯IAA标签。
- 证据等级：2024-06/07玩家评价反映武器方向、过大占格与格子广告问题；2026-05仍有格子广告抱怨。这些能证明反馈存在，不能证明全部玩家体验或现行完整规则。
- 借鉴：需要验证“还有空格却放不下”能否通过旋转、换姿势或一次移位解决；广告返回后仍要保住现有布置。
- 不照搬：不根据少量负面评论推断整个品类失败，也不据此配置广告次数。
- 来源：[TapTap评价页](https://www.taptap.cn/app/710112/review?os=ios)。本例不计入已核实的完整机制样本。

## 3. 海外补充对照

### 3.1 Gear Fight!：位置必须影响效果

- 资料：GameRes收录林彦丞2025-03-21体验拆解；作者描述当时为偏重IAA的混合变现。
- 资料可支持：准备阶段购入齿轮；盘面驱动器连接齿轮后运转，功能齿轮影响产出；准备与战斗分开。2025-04-14扬帆出海文章补充了6×4盘面及加速齿轮的描述。
- 借鉴：效果沿什么关系传递应看得见。本项目用猫—用品高亮呈现受益关系，不增加齿轮传动规则。
- 不照搬：直接从商店拖到盘面扣费，与我们已确认的购买→待放→入窝流程不同。
- 未核实：当前版本盘面和变现配置。两篇文章是同一产品，不能算两个样本。
- 来源：[体验拆解](https://www.gameres.com/911491.html)、[盘面说明](https://www.yfchuhai.com/article/10225159.html)。

### 3.2 Fortress Merge：空间扩展可以成为局内金币选择

- 资料：GameRes收录林彦丞2025-07-17体验拆解；海外混合变现对照。
- 资料可支持：准备时在有限土地放建筑，同类建筑可合并；作者描述早期空间较充裕，中期用金币针对性解锁所需土地。
- 借鉴：购买单位与购买空间使用同一局内资源时，可以形成明确取舍。
- 不照搬：不把建筑合并、非方形解锁和军队生产系统带进猫窝。本项目的扩容仍先讨论4×4→5×5→6×6。
- 未核实：当前版本具体解锁价格、广告空间限制、触控操作。文章个别小标题误写其他游戏名，这里只采用与标题及正文要塞玩法一致的段落，不引用模糊部分的参数。
- 来源：[产品分析](https://www.gameres.com/913333.html)。

### 3.3 Bag Fight（Voodoo）：操作时机的反向对照

- 资料：2026-10-02检索官方App Store说明。商店确认存在内购；本轮不凭免费或含内购推断广告收入占比。
- 官方文案强调战斗中快速整理背包、即时调整武器。这是产品宣传定位，尚未实测操作窗口。
- 借鉴：说明空间玩法也可以做实时压力，但本项目已经采用准备思考、战斗观看，不混入战斗中拖放，以免改变核心体验。
- 未核实：实际拖放是否在整场战斗随时开放、旋转与扩容细节。
- 身份边界：不是Tweleve Studio的同名近似产品，也不是Backpack Brawl。
- 来源：[Voodoo官方商店页](https://apps.apple.com/in/app/bag-fight/id6474043641)。

## 4. 广搜后未作为机制依据的材料

- 检索了《小小庇护所》相关公司资料，但本轮没有取得足够明确的旋转、待放和扩容操作证据，不能用宏观收入资料替代空间规则。
- 检索了Zego的《Backpack Hero: Merge Weapon》，[官方Google Play页](https://play.google.com/store/apps/details?hl=zh&id=com.ig.weapon.backpack)可确认含广告和内购，但本轮可读正文不足，不填写未核实的操作细节；也不与Steam《Backpack Hero》混同。
- 旧研究中的Steam《Backpack Battles》只保留为结构背景，见项目旧[核心循环参考](../../04_背包乱斗核心循环与机制参考_V0.1.md)；不算国内IAA样本。
- 搜索出现的破解包、免广告下载站、无来源的攻略聚合页不作证据。跨平台版本和转载不重复计数。

## 5. 本项目下一步

2026-10-03已回查花园特攻队、保卫向日葵官方更新与Gear Fight的上述来源；引用仍代表各自资料年代，没有据此声称其所有规则在现行版本完全相同。

本轮已形成[布阵操作与扩容规则](03_布阵操作与扩容规则_V0.1.md)，细化三类动作：拖入/取回、旋转/换姿势、整档扩容。每类动作说明成功结果、失败反馈、资源是否变化。总入口仍是[空间布阵草案](01_系统草案_V0.1.md)。

需要后续原型验证的假设：6×6窄屏是否拖得准；换姿势能否实际改善联动；4×4到5×5一次增加9格是否过度缓解空间压力。此处仅列验证目标，没有执行测试或宣称方案已验证。
