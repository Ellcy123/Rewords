# 激励广告系统 · 详细设计 V0.1

2026-10-03自主工作基线，依据[竞品调研及官方接口资料](02_竞品调研_首轮_V0.1.md)。首版只保留三处自愿激励视频。金额与次数的唯一配置来源为[经济表](../05_商店与经济系统/04_经济数值与预算_V0.1.md)，本稿定义流程、资格和失败处理。

## 1. 三个点位

| ID | 玩家入口 | 资格与奖励去向 |
| --- | --- | --- |
| AD_RUN_GOLD | 准备页“看视频，金币＋4” | 当前局、当前层处于准备阶段；同时满足每层/每局/每日额度；只加给这一局金币 |
| AD_RESULT_META | 成功通章结算“看视频，额外培养币＋N” | 本章已成功结算基础奖励；成功结果尚未领过视频额外奖且符合日额度；N由该结果常规收益B计算 |
| AD_HOME_META | 小屋“看视频，培养币＋40” | 符合日额度；发到账号培养币，不要求正在挑战 |

按钮必须显示真实金额、视频标识与剩余资格。结果奖励封顶时展示实际N，不笼统写“所有奖励翻倍”；首通、任务、签到和此前广告收入都不纳入B。

每层最多1次、每局最多2次金币补给，账号每日最多3次；成功结算每天最多2次，每个成功结果最多1次；小屋每天最多2次。因此一天最多7次成功激励，这只是上限，不是用户必看量或收入预测。

全点位共用60秒现实时间冷却，从成功观看并确认完成时起算，切换页面和×2战斗不缩短。当天额度与待核实订单优先于按钮冷却；没有资格就不播放。金额和额度仍以经济表为准，不在代码里写另一份。

## 2. 首版关闭复活

用户明确失败结束本局。本轮用户另授权自主完成剩余系统，因此采用“首版不开放广告复活”的工作方案，清掉此前广告例外待定项。这是助手在授权内的设计选择，不冒称用户逐项确认取消复活。

不提供死亡前续命、失败层加血重试、延长倒计时、广告跳层或重开保留局内物品；发生失败就按关卡规则清除局内财产。以后若要增加复活，必须作为改变核心失败体验的新方案讨论，不能悄悄恢复旧Demo行为。

## 3. 不打断正常闭环

无强制插屏、自动播放、开屏领奖视频或战斗中广告。首次教学不弹补给提示，不用广告填补必要购买缺口；准备页的补给仅为次级入口，金币不足时说明差额，不自动播放或跳转。

基础层胜/章末奖励先自动入账，再展示额外视频按钮；关闭结算不会丢基础奖励。每日任务、签到和猫咪解锁均不要求视频次数。

小屋保留“最近通关额外奖励”入口，可继续领取最近一次成功通章尚未使用的视频资格。下一次成功通章结果替换旧的未申请资格，旧资格不累计成仓库；开始新局、失败、跨日不替换。已申请的旧广告订单独立保存原resultId及奖励快照，不占用“最近结果”这个展示槽，也不阻塞新章末基础奖励。

例如R1广告待核实时赢得R2：先正常提交R2终局、基础奖和解锁，最近结果更新为R2；R1订单继续按原额度核实，成功后只发一次R1额外奖。R2视频按钮在R1订单终结前暂不可用，原因写“有一份奖励核实中”；普通游玩和R2基础领奖不受影响。若又赢R3，则最近资格变R3，不能把未申请的R2积存。展示提示“下一次通章会更新”。

## 4. 观看订单状态

统一状态：可申请→资格预占/加载→播放→结果核实→已发奖，或明确取消/失败。每次请求具有不可复用的订单ID，固定账号、点位、原runId/floorId或resultId、奖励数额与运营日。

1. 点击后检查资格、冷却与当前页面状态，预占该运营日对应额度并锁定奖励快照，再请求SDK。
2. 加载无填充、已知错误或明确未完成观看：不发奖、不消耗成功次数，释放预占，保持正常游玩。失败不触发成功冷却；按钮可显示“暂时没有视频”，网络请求有防连点退避。
3. 完成观看证据成立：以原订单奖励事务将金额、成功次数和已发奖状态一起提交。重放回调只返回原结果，不再加钱。
4. 回调缺失、进程退出或网络中断：保留“待核实”，先查询原订单/平台可用证明；不能既释放额度又在迟到回调无条件发奖，也不能用本地计时到30秒推断完整观看。确认完整观看可从待核实转已发奖；明确未完成则转失败并释放预占。
5. 未核实期间，原预占占用额度；同一账号不并行播放新视频。显示“奖励核实中”，允许普通入口与无关玩法继续，提供重查状态。无可信完成证据不先给可消费金币；只能通过后续核实或明确失败终结该订单。

所有额度检查计算已完成＋仍预占的订单，不能多设备各自先通过上限检查。正式账号需持久化事务与平台回执适配；本地网页模拟不能声称已经实现防刷或真实广告收益。

## 5. 局内奖励和跨日边界

金币订单未完成时，当前局保持本层准备状态，可摆放、查看，但不能开战、放弃或替换这一局；若平台报告取消/失败立刻解除。界面解释“先确认本次补给结果”；不得先让玩家结束本局，再把回调金币加到新局。

正常加载/播放使用平台允许的取消或关闭路径，不遮盖SDK控件。进入结果核实或恢复查询后，120秒仍无证据时提供“继续核实”与“放弃这次补给，继续游戏”；120秒是本项目等待提示初值，不是视频观看时长或平台完成判据。等待时可重查；选择放弃须说明“尚未确认完成，本次不会发奖”，随后终结原订单、释放预占和原局操作锁。玩家不会因无回调被无限阻塞在准备页。

明确取消/失败以及玩家主动放弃核实均为不可自动翻转的终态。其后迟到回执只写审计记录并显示已关闭订单的原处理结果，不自动补发、不扣新日额度、不向新局转币；发现矛盾回执提供反馈记录供运营核查，本轮不承诺自动补偿或新增补偿币。仍处于待核实的订单则可按原订单正常补发，仍占原日额度。两种情况必须区分，不能笼统说“迟到都发”。选择等待不会被120秒计时器自动当失败。

工程验收需按发行平台验证查询/回执能力；平台没有查询API时不能伪造查询成功，只能等待可用证据或由玩家明确放弃。上述终态政策不依赖假定所有SDK都有服务端查询。

运营日统一北京时间05:00。订单按点击前服务接受预占的日期锁定，04:59开始、05:01完成仍占旧日；今日额度可以另用，但前一订单未完成前不能开第二条。切日不释放待核实订单，也不改变已锁奖励。冷却按实际成功时间算。

结果额外奖属于账号资源，即使回小屋，原resultId仍有效；结果基数锁定，不随之后升级或新金币变化。金币必须属于原局，不能折成培养币兜底。

## 6. 平台适配原则

使用发行目标平台官方的完成观看回调及可用服务证明。抖音文档在相应版本提供完成数量count时优先按其语义判断，旧字段isEnded仅按该版本文档作兼容；快手及其他平台按各自接口，不硬套相同字段。缺字段、关闭事件、已播放时长都不能直接当成完整观看。

当前没有接入发行SDK，也未选择平台；上述是统一订单与玩家结果要求。平台只提供客户端证据时需要如实记录安全边界，不能把一个布尔回调包装成服务端验证。具体说明与查询日期见本目录调研文件。

## 7. 数据和验收

记录入口曝光、主动点击、加载结果、开始播放、结束原因、证明状态、到账结果、耗时、点位、原运营日与局/结果ID；实际收益以平台返回数据为准，不在策划表凭观看量估eCPM。

优先观察：未看广告的首章/正常章通关率、每局视频打断数、视频失败后流失、已完成未到账比例、主动观看占比、额外资源对培养速度的影响。不能把观看次数越高直接等同设计越好。

验收至少覆盖：不看广告完整过章；取消/无填充无扣次；多次回调一次到账；预占阻止超过额度；跨日旧订单归旧日；跨局不串金币；关闭结算基础奖仍在；结果B封顶正确；强退恢复订单；无广告复活入口。策划复核与后续功能测试按Luna/xhigh执行。
