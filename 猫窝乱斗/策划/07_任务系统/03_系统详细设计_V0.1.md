# 任务系统 · 详细设计 V0.1

2026-10-03自主工作基线，依据[竞品调研](02_竞品调研_首轮_V0.1.md)。任务条件归本系统，奖励金额统一引用[经济表](../05_商店与经济系统/04_经济数值与预算_V0.1.md)。本稿为待实现规格。

## 1. 定位与入口

用六个一次性目标帮助玩家理解构筑，再用三个轻日常承接正常游玩。没有周活跃、任务通行证、广告任务、强制培养任务或每天买卖指定物品的任务。

小屋只放一个“任务”入口，面板内分“成长”和“每日”。成长初始可看，每日页在第一场战斗终局后开放；解锁当日已发生的合格事实回填。进度提示不盖住布阵和战斗，不要求先接受任务。

## 2. 六个成长目标

所有成长目标独立累计，列表按下表排列，不以领取上一个作为下一个开始计数的条件。历史已完成事实可回填，奖励账号终身一次。

| ID | 玩家看到的目标 | 完成事件与边界 |
| --- | --- | --- |
| G01 | 让一件用品连接猫咪 | 准备阶段一次合法落下后，产生至少一条有效连接；不要求该时刻触发条件已满足，但无目标适配、斜角或被重复类型去重的线不算 |
| G02 | 赢下第1章第1层 | 首次1-1胜利结果提交；战斗动画未结束不影响已提交事实 |
| G03 | 让猫咪发动一次本领 | 任意正常战斗终局提交的技能次数≥1；追加爪的多段伤害仍是一件技能事件 |
| G04 | 通关第1章 | 第1章末层首次胜利结果提交 |
| G05 | 用一件用品照顾两只猫 | 任意正常战斗的开场快照中，同一用品实例有两只有效受益猫，并在该战斗终局提交。要求用品自身效果有直接作用，不用只增加C06/C08计数的空倍率连接完成 |
| G06 | 结识三位猫伙伴 | 永久收藏已解锁猫数≥3，不是同时买到三只；C01、1-3的C03及首章通关C02即可达成 |

G05的“直接作用”采用用品效果类型适配：开场盾、攻速、攻击、正常可发生的事件加值均可；限血量触发的效果只需该猫具备相应事件，不要求此次恰好触发。没有自身技能盾的猫接I14不算直接受益。与[商店的直接适配判定](../05_商店与经济系统/03_系统详细设计_V0.1.md)复用一套定义。

G01是布阵教学事实，落下即记永久完成；G03/G05在正常终局提交，防止强退重播反复累加。成长完成后可以稍后领取，不会过期。

## 3. 三个每日目标

| ID | 玩家看到的目标 | 计数规则 |
| --- | --- | --- |
| D01 | 赢下3层 | 同一运营日累计3次楼层胜利；首通/重刷、不同章节均可，同一战斗只能计一次 |
| D02 | 完成1场战斗 | 正常胜利、生命耗尽或超时终局均可；主动放弃、加载失败、纯动画回放不算 |
| D03 | 发动6次猫咪本领 | 正常终局提交该场所有猫技能事件数；赢或输都算，同一技能多段追击仍计1次 |

不要求完整通章才能完成日常。自然打一段也有进展；不能保证任何阵容打一场就完成全部三项。每日奖励总额见经济表，进度满后不继续增长、不新增隐藏阶梯。

每日目标按[统一运营日](../08_日常福利系统/03_系统详细设计_V0.1.md#2-统一运营日)归属，第一场终局前的当日事件也保存，因此每日页出现时不会丢掉解锁场的贡献。

## 4. 领取、换日与离线

任务状态为未完成→可领取→已领取。点击领取将奖励入账与状态变更作为同一事务；“全部领取”只处理当前已完成项，不代玩家看广告、不额外放大金额。红点只表示有可领项，不为未完成项或新日期常驻。

每日已完成未领取奖励在下一次账号同步换日时自动入账，并提供一条合并提示；金额仍归旧日来源键。当天手动领取与跨日自动领取竞争时只成功一次。未完成进度换日清零，没有补领未完成任务。

每个正常终局具有唯一battleId，胜利层另有runId＋floorId；同一局重复打开结算不再记数。恢复重播未结算战斗只在最终提交时记一次。战斗跨05:00，整场技能和胜利都记到终局被接受的运营日，不把半场技能拆到两天。

正式账号由持久化服务确定日期。离线产生的未确认事件可以保留待同步，但只在服务接受终局时归日和发奖，不据本地设备日历补开历史任务；已确认并完成的成长项不丢。网页本地示意可模拟日期，不能声称已经有服务端校时。

## 5. 页面和引导

卡片显示目标、当前进度、奖励和一个状态按钮。未完成项的“前往”只跳到有关入口，不强制放弃当前局：有在玩章节则回当前准备/恢复入口，没有则去楼层页。G06指向猫咪图鉴，展示明确的关卡解锁条件。

完成提示合并在战斗结果或回小屋时出现，避免一次首通连续弹出六个弹窗。成长任务全领完后保留可折叠的已完成记录，每日页成为默认页。

## 6. 保存与验收

保存成长完成事实/领取标记、每日日期/计数/领取标记、已消费终局ID。一次性奖励来源为账号＋G编号；每日为账号＋运营日＋D编号。页面红点从领取状态计算，不另存一份容易过期的布尔值。

验收重点：首章首次通关自然达成G02/G04/G06；G05同实例服务两猫，不能用两件各服务一猫凑数；任务先做后开页仍计数；失败终局计D02/D03但不计D01；弃局不计；跨日领取与回放不会双发。数额复算、规则检查及后续实现测试遵守指定Luna/xhigh流程。
