# 《MBTI智斗计划短视频版》设计规范总则

> 文档级别：项目最上层规则  
> 当前状态：用户已确认  
> 生效日期：2026-08-25  
> 修改权限：未经用户明确确认，不得修改本文件

## 1. 本目录的作用

`01_设计规范` 是《MBTI智斗计划短视频版》的上层设计规范区，只存放项目总则和各设计领域的上层规则，不存放具体技能、角色、世界观或剧情方案。

只有满足以下条件的内容，才能进入本目录：

1. 内容明确属于本项目；
2. 内容属于需要长期约束后续设计的上层规则；
3. 想法由用户提出，或由 Codex 提出后获得用户明确认可；
4. 文档清楚标记确认状态与生效日期。

网络资料、灵感收集、候选方案、具体设计、Codex 单方面提出的规则和仍在讨论的内容，不得放入本目录。已经确认的具体设计进入与 `01_设计规范` 同级的对应设计目录。

## 2. 项目设计目录的分类

项目规则和具体设计根据内容归入以下同级条目区：

| 编号 | 条目区 | 收录内容 |
|---|---|---|
| 01 | 设计规范 | 项目总则与各领域上层规则，不收录具体设计 |
| 02 | 技能设计 | 已确认的具体能力、限制、反制、变格与技能名单 |
| 03 | 世界观设计 | 已确认的世界底层公理、时代、空间、组织、资源与世界变格方案 |
| 04 | 角色设计 | 已确认的角色身份、人格欲望、关系、经历、造型与角色弧光 |
| 05 | 智斗与剧情 | 已确认的对局、谜题、公平反转、主线、单集事件与信息披露方案 |
| 06 | 短视频制作 | 已确认的时长、节奏、钩子、分镜、镜头、对白、声音与发布形式 |

当前没有确认内容的设计区不必提前建立空目录。获得确认后再创建对应目录和文件。

## 3. 文档层级

设计规范分为三层：

1. **最上层规则**：本文件，规定项目如何记录和修改正式设计；
2. **领域上层规则**：存放在 `01_设计规范`，例如《技能设计上层规则》，规定某一设计领域必须遵守的原则；
3. **具体设计文档**：存放在同级设计目录，例如 `02_技能设计` 中的正式技能表。

下层文档不得违反上层文档。如果出现冲突，先停止修改并向用户指出冲突，由用户决定是否修改上层规则。

## 4. 确认与收录流程

后续所有设计按以下流程处理：

1. 用户提出想法，或 Codex 提供候选方案；
2. 在对话中讨论、修改和测试；
3. 用户明确表示认可、确认、采用或同意；
4. Codex 判断它属于哪个条目区；
5. 上层规则写入 `01_设计规范`，具体方案写入对应的同级设计目录；
6. 在文档中更新确认状态和变更记录。

“正在讨论”“可以考虑”“先看看”和未得到回应的 Codex 提案，默认仍是候选内容，不自动进入正式规范。

## 5. 最上层规则的修改锁

本文件是唯一现行的项目最上层规则文档，不得因为实现方便、内容扩展或 Codex 自行判断而改动。

只有发生以下情况之一，并得到用户明确确认后，才能修改：

- 用户新增一条最上层规则；
- 用户明确修改一条现有规则；
- 用户明确废除一条现有规则；
- 用户确认两个上层规则发生冲突时的处理方式。

修改时必须直接更新本文件，并在“变更记录”中注明日期、修改内容和确认状态。不得悄悄用新文件绕过本规则，也不得删除旧记录来掩盖变化。

## 6. 其他规范与具体设计的修改原则

- 用户确认的新上层规则写入 `01_设计规范`；用户确认的具体设计写入对应的同级设计目录；
- 用户明确推翻旧设计时，应修改正式文档，并保留简短变更记录；
- Codex 可以发现问题、提出修改建议，但在获得用户确认前只能形成候选稿，不能擅自改变已确认规范；
- 为修正错别字、失效链接或不改变含义的排版问题，可以进行维护性修改，但不得借维护改变设计含义；
- 如果无法确定一次修改是否改变设计含义，默认视为实质修改，等待用户确认。

## 7. 角色视觉与 MJ 提示词总则

### 7.1 角色年龄与审美优先级

- 本项目主要角色的视觉年龄统一为 **20 岁左右**；
- 不论角色属于哪一种 MBTI、性格多么阴暗或极端，人物提示词都必须首先保证角色年轻、好看、具有主角吸引力；
- 人格特征通过眼神、表情、姿态、服装、道具和能力表现传达，不得用显老、丑化、邋遢或刻板的“书呆子化”等方式代替人格设计；
- 服装优先采用现代或现代幻想设计。除非具体角色设定另有需要，不默认使用中世纪长袍、维多利亚礼服、蒸汽朋克护目镜或重装奇幻服装。

### 7.2 默认画风参考图

当前确认的项目默认画风参考图为：

`https://cdn.midjourney.com/f2a8927b-c600-4e60-bb60-4bde8dceaa7e/0_1.png`

后续所有角色的 Midjourney 提示词默认写入：

```text
--sref https://cdn.midjourney.com/f2a8927b-c600-4e60-bb60-4bde8dceaa7e/0_1.png --sw 300
```

这张图用于统一项目的半写实程度、柔和绘画塑形、哑光手绘材质、简化但好看的面部结构和整体完成度，不用于让其他角色机械复制药水姐的脸、发型、眼镜、配色或服装。若参考图对具体角色的构图或造型干扰过强，可以调整 `--sw`，但不得在未说明的情况下移除默认画风参考。

### 7.3 角色提示词的统一结构

药水姐当前确认版本作为后续角色提示词的结构范例。每个新角色的完整提示词依次写明：

1. 原创角色身份、20 岁左右的明确年龄和角色定位；
2. 以好看为优先的年轻面部、五官和体态描述；
3. 发型、眼镜、颜色或其他专属识别元素；
4. 能够体现人格和智斗状态的眼神、表情与姿态；
5. 现代化服装、能力道具和代表性视觉效果；
6. 明确的景别、机位、人物朝向与视线；
7. 统一的半写实绘画风格、材质、光线、配色和背景；
8. 画幅、模型、风格参考图与必要的排除项。

用于第一轮角色正面定妆时，默认采用平视正面机位：人物面部和身体朝向镜头、直视观众、双肩平齐，镜头与眼睛同高；不得自动使用仰视、低机位、侧脸或三分之四侧脸。剧情镜头另行设计，不受正面定妆机位限制。

### 7.4 默认风格描述与参数格式

角色之间可以拥有不同的五官、服装、颜色、能力特效和性格表演，但提示词的风格骨架默认保留以下方向：

```text
stylized semi-realistic character design, simplified beautiful facial planes, soft painterly modeling, matte hand-painted textures, gently grouped hair shapes, restrained costume details, subtle brushwork, refined but intentionally understated, slightly imperfect painted edges, visually attractive above all else
```

当前默认参数格式为：

```text
--ar 9:16 --v 8.2 --raw --s 140 --sref https://cdn.midjourney.com/f2a8927b-c600-4e60-bb60-4bde8dceaa7e/0_1.png --sw 300
```

排除项根据角色调整，但通常应避免显老面相、写实皮肤毛孔、根根分明的高精度发丝、锐利微观细节、光滑塑料感 CGI、强烈镜片反光、仰视机位，以及文字、字母、标志和水印。
