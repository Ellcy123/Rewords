# 前向分支对话规则 V0.1

## 目标

玩家不是逐项清空 NPC 的话题列表，而是在与 NPC 进行一次向前发展的交流。
选择“为何不信自杀？”后，NPC 回答这个问题，并通过自己的回应引出下一次决策，不返回“自杀／猫／找谁”的根菜单。

## 选项怎么产生

- 先生成本段完整对白和动作，再根据末尾的具体处境生成 2～3 个回应；自然结束时可以没有选项。
- 所有选项承接眼前同一件事，提供不同态度或不同追问角度。不要为了凑数突然引入人设里的猫、喝茶、指路等其他话题。
- 每个选项 2～12 字，用玩家马上会说的话；不能让玩家先理解一段抽象行动策略。
- 后续对白可以由主角与 NPC 来回说，但主角只延续玩家已经选定的意思，不代替玩家做新决定。
- 选项在本段全部对白播放完后出现，因此可以引用本段刚说出的信息。疑问可以探索未知答案，不等于宣称新事实；不能把从未提及的私密事实直接当前提。

例如 NPC 说：“她连我的票都买好了，我还叫她自己走。”
可接“你们吵什么？”“你不是故意的。”“她怎么回你的？”。
这只是结构示例，不是固定台词或分支树。

## 选择之后

选中一个回应后，记录本次选择和其他错过的回应，生成新节点；不要求玩家问遍所有信息。
本次会面内不能重新补发旧选项，也不能把同一个看材料动作换一句话再塞回来。
选项 ID 每次重新生成，旧节点 ID 不能用于后续节点。

“错过”不等于角色听过或玩家承诺过：未选内容只保存在分支元数据里，不进入 NPC 的实际见闻记忆，也不产生物品或剧情效果。
跨会面仍基于实际记忆接话，不自动重播开场；后续新事件、新证据自然带回旧话题，与本次会面循环菜单是两回事。初版不做全章节永久封禁某个话题。

## 会面长度与自然收尾（补充）

- 一次会面上限24句，主角和NPC合计；每次显示的一条对白算1句，不按句号计数，动作说明不另计。
- 通常接近18句开始收尾；短句很多时，第5次玩家选择后的回应也必须收尾，可以更早自然结束，不需要凑满。
- 每次生成前提供已播放句数、剩余句数、本轮最多生成节拍数、是否必须收尾。预留玩家选择台词和NPC告别的位置，避免到最后才生硬截断。
- 收尾先接住玩家的这句话，再说明符合人设的离开／结束理由。比如小春借扫神社平复情绪，律用玩笑回到报摊，千代去收拾旅馆，警员回到手头事务。
- NPC可以想独处、累了、回避追问，不必人人说“要上班”。受伤者要休息，已经安排保护任务的人不能突然换成无关工作。
- 末句由NPC说完，不再追问或抛新线索，options为空。玩家逐句看完告别后点“返回场景”，不自动跳走吞掉对白。
- 收尾不能取消已经答应的最后一次材料交付；相关动作仍在对白实际播放完后落地。
- 结束后禁止通过出示材料／转告消息重开本次聊天。之后在场景中重新发起会面，仍按原规则消耗交谈时间。
- 程序根据已播放事件检查硬上限，不只是给模型一个建议。刷新页面和恢复存档不重置预算；不删除旧存档里已经说过的对白，旧版已超长会面在下一段补一次告别。
- 告别中的工作意向不直接改变NPC地图位置，也不额外推进游戏时钟。

### 收尾专项验证

2026-09-05：在构造的18句前文上下文中，真实DeepSeek为小春生成“去扫神社、手里有点事做”的收尾，为律生成“整理报摊”的收尾；两次均不再生成选项。全部结果见对白测试记录中的“会面收尾专项”文件。
这只验证收尾场景，不代表此前的案情编造、语义重复等问题已经完全解决。

## 人设与系统动作分开（执行规则）

角色的开场引子和初次展示材料目标只在初次开场使用；已经开始交流后，不强迫每轮完成原始展示任务。
人设、知情范围、个人倾向仍保留，AI 决定具体对白、回避方式、情绪与回应角度。

系统只提供合法动作目录，如查看材料、索取实物、纠正证词、签写说明等。它不是玩家菜单。
AI 写选项文案，普通接话绑定空动作；只有明确请求执行某个动作的选项才绑定动作 ID。
动作仍由程序检查所有权、前置条件和实际播放进度后执行，不能靠一句对白凭空拿物品或改案情。
选择出示材料／转告消息也会离开当前节点，不在之后自动补回其余选项。

## 校验与失败处理

- 结构校验：短选项、唯一 ID、动作合法、不能在未选时替玩家讲话。
- 分支校验：已选／错过的相同文案及已放弃的动作不重复；完整已播放主角台词也参与去重。
- 模型审校：检查同义回退、跳话题、玩家立场、动作语义与新增案情；只用正式事实判断历史，旧轮生成内容不能自动升级为事实。
- 审校给出的问题送回生成器修正；最多两次生成。真实AI续聊在未到收尾阶段连续失败时返回可重试错误，恢复该次请求前的节点、时间、物品、信息送达和记忆，不把技术失败演成NPC告别。已到预算上限才使用保底告别；未配置AI的离线演示除外。
- 独立审校不是正确性证明，仍可能漏检或误判，需要保留真实多轮记录继续评估。

## 验证方式

自动测试覆盖多轮推进、选项过期、未选内容不是 NPC 记忆、动态选项的查看／拿取效果，以及语义审校反馈重试。
真实模型使用隔离内存存档连续抽样，保留全部成功与回退结果，不重置网页中的玩家进度。
本次仅改变对话生成和相关校验，不调整案件真相、地图、行动时间或七日结构。

## 2026-09-05 本轮验证结果与剩余问题

- 71 项自动测试通过，类型检查和生产构建通过；本地网页与后端健康检查正常，运行提示词版本已更新。
- 多次真实抽样全部留在“对白测试记录”目录，包含失败草稿，不只保存成功案例。
- 最后一轮小春、千代合计实际播放 7 段：5 段为 DeepSeek 生成，2 段进入保底。小春开场保底后连续生成了 3 段新对白；千代第 3 段因连续校验失败收束。
- 固定 ask／daily／route 菜单已从生产路径删除，普通选项由模型生成；硬性去重、动作约束及过期 ID 由程序执行。
- 不能把结构通过当成质量达标：真实输出仍出现错过问题的同义回流，以及东京、信件内容等未设定细节。语义审校也出现“把询问未知答案误当新增事实”的误判。当前版本尚不能保证这些语义问题完全消失。
- 下一轮应重点评估语义审校的误判／漏检、选项同义去重和连续生成的保底率，不把扩大人设字数当作已验证的解决方案。

## 仓促结束修正（2026-09-05 后续）

实际玩家记录显示：仅经历2次选择、10句已播放对白，尚余14句空间，第二次回复因player_intent校验连续失败，被旧逻辑替换成一句“去扫神社”的告别。这不是达到24句上限。

现已区分技术失败与剧情结束。失败不消耗重复时间、不留下失败候选的记忆或选择记录；原选项可以重试。收尾预算不因此盲目增加。
节奏分为展开、准备收尾、最终告别：约14句或第4次选择先收拢当前话题、露出工作/情绪变化，最终阶段先回应玩家再用2～4个节拍过渡（仍服从剩余额度）。安慰选项不授权主角自动追查新案情，主角不必每段强行插话。

92项自动测试通过，包含失败后重试不重复记忆/时间、预算仍然有效、保底告别先回应安慰。只读重放玩家刚才的选择仍遇到结构校验失败，但没有再伪造剧情结束；技术生成成功率仍需继续改进。没有改写玩家已经看过的存档对白。
