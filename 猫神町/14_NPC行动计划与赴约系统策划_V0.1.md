# 《猫神町》NPC 行动计划与赴约系统 V0.1

> 2026-09-07。已实现的最小版本：每名 NPC 的运行状态增加一个 `actionPlan`，当前仅小春拾绪对白可产生新会面计划。不是全员自主日程系统。

## 1. 已确认方向与职责

人物说“去家里等你”应能落实为行动，而不只作为记忆文本。生成对白的 AI 同时决定是否邀请、地点和时间，输出结构化计划；不增加另一个 AI 重判其行动动机。程序检查地点、时间、身体状态、冲突与实际台词来源，再按游戏时钟执行。

人设描述“我是谁”，历史记忆描述“经历过什么”，`actionPlan` 描述“接下来准备做什么”。计划和执行结果同时进入人物记忆，生成时只读取该 NPC 自己的计划。

## 2. 数据结构

存档字段：`npcStates[npcId].actionPlan`，无计划为 `null`。示例：

```json
{
  "id": "plan_event_7",
  "type": "meet",
  "targetNpcId": "player",
  "locationId": "loc_home",
  "arriveAt": 780,
  "waitUntil": 900,
  "status": "planned",
  "reason": "到旧居继续聊姐姐",
  "quote": "一点，雨宫家旧居。我等你到三点。",
  "sourceEventId": "event_7"
}
```

时间为绝对游戏分钟：`(day - 1) * 1440 + 当日分钟`，例如第一天 13:00 = 780。理由可以是自然语言，但地点 ID、时间与状态必须结构化。

生成结果额外携带 `action_plan.beatIndex`，指向 NPC 的约定台词；转为存档计划后使用实际播放事件 ID，不再保留待播索引。完整生成结果通过校验不等于约定已经发生。

## 3. 触发与记忆

- NPC 明确提出邀请或答应具体会面时，生成 AI 同时填写 `action_plan`；台词需表达与字段一致的地点和时间。假设、回忆、含糊的去向以及遥替 NPC 单方面安排不形成计划。
- 对应 NPC 台词实际显示后才保存，来源必须是该句原文。未播放的候选不建计划、不解锁目的地；生成失败整体回滚。
- 新计划在旧计划仍有效时替代旧计划，旧计划取消事件留在记忆。没有新计划（输出 `null`）不清除旧计划。
- 约定目的地加入已发现地图。玩家可以赴约，也可以不去，不因 NPC 邀请就自动移动玩家。
- 到达、过期、取消、实际会面都有事件及 NPC 记忆；只向玩家显示其有权知道的内容。

## 4. 首版执行规则

| 项目 | 当前行为 |
| --- | --- |
| 支持类型 | `meet`：NPC 到已有地点等待遥 |
| 当前生成入口 | 小春的拾绪试玩；普通交谈和其他六人暂不产生此类新计划 |
| 时间范围 | 至少留 60 分钟；抵达在未来 24 小时内；抵达与等待结束在同一个游戏日的 09:00～18:00，且不超七日期限 |
| `planned` | 约定已保存，未到达；到时间才改变 NPC 位置，没有额外动画或途中位置模拟 |
| `waiting` | 已在目的地，等待到 `waitUntil`；玩家仅进入地点不算完成 |
| `completed` | 玩家在有效等待时间内点击该 NPC 开始会面；生成对白能读到已完成的约定 |
| `expired` | 等候到期，不再专门等待；仍留在当前位置，首版不凭空安排返程 |
| `cancelled` | 新计划替代、身体状态不允许、或案件行动冲突；原因进入记忆 |
| 正在交谈 | 不在对话中搬走说话者；结束当前会面后处理已到期的移动，时间不倒退，若等待窗口已过则过期 |
| 案件优先级 | 原旅馆事件及警员移动优先，避免新计划覆盖案件行动；时间跳跃逐个处理到达和过期 |

计划不是关系数值变化，不执行赠礼、材料交付、签写或案件裁决。七人日常作息、NPC 之间互约、计划队列、玩家主动改约／取消按钮和自动返程均未纳入首版。

## 5. 界面与存档

页面增加“会面约定”，显示人物、地点、到达／等待时间与状态。未在现场时“已约定”不代表已经亲眼确认对方到场，不在地图泄露其他地点的实际 NPC 位置。

沿用 `saveVersion: 3` 兼容扩展：旧 NPC 字段默认 `actionPlan: null`；旧心绪段落默认无候选计划。不扫描旧台词倒建行动，不清档。刷新恢复待播位置和已保存计划，过期播放请求不会重复建立计划。

## 6. 验证与剩余问题

- 146 项测试通过，包括计划在台词播放后生效、未播退出、地图发现、定时移动、开始会面完成、时间跳跃过期、次日计划、旧档／SQLite 恢复、重复请求、替代、失败回滚、身体限制、案件优先、远处位置隐藏与交谈时延后执行。
- [真实 AI 定向记录](对白测试记录/2026-09-07T11-11-15-936Z_行动计划定向验证.md)：固定前置邀约后，真实 AI 答应 13:00 在旧居等至 15:00，输出对应计划；播放保存后实际执行到达、等待、会面完成。
- [较早失败记录](对白测试记录/2026-09-07T11-10-11-026Z_行动计划定向验证.md)：AI 口头答应但遗漏字段，已补充输出格式和提示。成功抽样不是稳定生成率保证；若只说了邀请却未生成有效对象，页面不会显示正式约定，不应当作已排期。
- 浏览器使用 5174／8790 隔离固定演示验证了约定栏、旧居解锁、13:00 小春出现、已见面及刷新恢复；原玩家存档未推进。固定演示不冒充真实 AI 自主邀请。
- 时间／地点字段与台词的语义一致目前依赖生成提示，程序校验可执行范围和原文锚定，不解析所有中文时间表达。仍需多场景验证自然邀请密度、取消表达和约定回收；原有重复、事实漏检与收尾问题继续保留为质量项。

## 7. 开发验证入口

`npx tsx scripts/recordMeetingPlan.ts`：隔离内存存档，前置邀约为固定测试，回应及计划为真实 AI；保留原始候选和请求结果，不记录密钥。

同时设置 `CAT_HEART_PREVIEW=1`、`CAT_MEETING_PREVIEW=1` 后运行 `npm run dev`，启动固定演示与内存存档在 5174／8790。两项同时启用才切换会面演示，不影响普通 5173／8787。验收后停止预览进程。
