# 七日疑案：首版实现与验证

日期：2026-09-05。本文记录代码状态，不替代排期或案件真相文档。

## 已实现

- 7 人／8 地点／18 个物品定义，案件真相和知情表留在服务端。
- 地点发现只看实际播放节拍、实际阅读材料；警署、诊所、旅馆支持唯一地点简称。
- 多 NPC 场景、无人场景、主动会面、聊天／赠礼分支及统一玩家对白 UI。
- 物品所有权、查阅手记、出示与赠送分离；动态说明在实际签署后才存在。
- 每人独立事实集合和记忆，信息转告／出示／赠送／千代电话均记录明确送达。
- 对话记忆只写已播放内容；跨日保留；摘要反思与规划分离。
- 千代独立选择暂缓、写说明、联系律或联系警员。律收到消息后独立选择接触、威胁、袭击或放弃。
- 游戏时间逐节点执行，支持提前在场、袭击中打断、离开与事后到场；求助不瞬移。
- 生死状态约束交谈、赠礼和规则记忆；死亡不补发材料。
- 七日收束、七人状态结果、AI结局与事实保底。
- 新数据库与旧章节独立；损坏／版本不匹配不能静默重开；密钥和数据库保持忽略。

- `npm test`：56 项通过，涵盖新数据契约、动作与记忆、地点发现、前中后到场、非致命计划、警方到场、持久化、七日结束、Provider校验与审校回退。
- `npm run build`：类型检查和生产构建通过。仅依赖库的纯注释处理提示及 SQLite 实验性提示，无构建失败。
- 浏览器实际验证：新版页面载入，地图初始三处；商店街两人独立选择；结束未交谈会面仍为10:00，没有扣除两小时；材料入口和手记导航可见。
- 七人各两段真实 DeepSeek 抽样在 `2026-09-05T07-00-47-715Z_杀人案重构抽样.md`：13段模型通过，1段因替未选择的玩家说话而进入保底。

- 杀人、打断、死亡等分支使用可重复的离线规划器验证；没有用真实网页存档强行制造死亡。
- 真实模型抽样均使用独立内存存档。网页操作仅到商店街并退出未交谈会面，当前新章为第1天10:00。旧 `demo-save.sqlite` 保留。

## 本次实测后补强

1. 开场不得让尚未选择的玩家先发问。
2. 材料选项需要对白已经提到材料，不能从隐藏 Prompt 直接冒出来。
3. 展示／递出材料必须和结构化同意动作一致；当前持有人明确注入 Prompt。
4. 票上的“次日”属于三周前，不是游戏中的明天；具体发车时刻不能编造。
5. 固定案件材料与人物声称分开。加入独立事实审校，降低临时编造案情和越权代玩家表态的风险。

## 明确边界

- 只有千代改口这一条高风险行动链完成，不是任意角色的通用行动沙盒。
- 其他 NPC 不执行旧版每日三人轮换，也没有新增门禁或钥匙系统。
- 反思目前是实际会面摘要，未实现独立模型的高层长期人格反思。
- AI 台词仍可能出现措辞生硬、角色否认与实际真相的区分不清等问题；不能用测试通过宣称“有人味”已完全验收。
- 旧 Provider、旧 Prompt、旧记录器及 `*.legacy.ts` 是历史参考，不进入当前游戏运行链路。新默认测试入口只覆盖新章。
- 本次不含美术生产、Unity 移植、额外角色杀人链或联网部署；没有执行 Git 提交或推送。
