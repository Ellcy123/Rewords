# 猫神町 · 七日疑案 Demo

当前版本：`0.7.0-sunset-case`。React 网页客户端 + Fastify 权威状态服务 + DeepSeek。
本章改为“被当成自杀结案的杀人案”，不再执行旧失踪案的零号站台事件。

## 拾绪 · 九种心绪与七人接入（2026-09-12）

**玩家认知账本 `shixu-v17-player-knowledge-ledger`**：朝雾遥的人设只决定语气与行为倾向，不再当作案情知识。存档独立记录玩家已知事实：阅读材料或NPC实际说出后才写入；首次听见时遥必须当作刚得知，后续会面才可默认知道。NPC仅在心里使用、用来撒谎或回避的私密事实不会记入玩家认知。旧存档保留进度，仅从开场明示前提和已读材料重建肯定已知内容，不倒推未标记的旧对白。

**信息压力对白 `shixu-v18-information-pressure`**：普通对白优先从当前NPC知道、玩家尚未得知的事实中选择当前最相关的1—2项，不能再以安慰、理解、感谢或比喻作为一段的主要进展。没有可自然公开的新事实时，必须产生矛盾、具体要求、交易、决定、威胁、行动或明确的下一调查目标。七个人各自增加可变形的“剧情施压方向”，AI依当前人设、秘密、已知信息和玩家态度选择怎么推进，不是固定台词树。拾绪的职责改为影响NPC交出或隐瞒什么、提出什么条件、作出哪个决定及是否采取行动，不再负责延长情绪对话。每段AI还必须结构化声明本次具体推进，供审校拒绝“有语气、没有事”的空转。

**档案官 AI `archive-agent-v2-readable-dossiers`**：档案页只显示独立的人物档案与事件档案，不陈列道具或原始材料。档案官不参与写对白，只读玩家已实际看到的对白、旁白、材料和公开事件；打开档案页时按批整理新见闻。明确姓名或稳定身份才能解锁人物，具体经过、参与者或后果足以成为调查对象才能解锁事件。每条信息保留原始事件来源、获得时间和“他人说法／亲眼所见／材料记载／已确认／存在矛盾”状态；NPC的指责不会被自动写成真相。一条见闻可同时更新人物和事件，两个面板通过参与关系双向跳转。AI不可用时保留旧档案并明确标注，不伪装成已整理。
道具与已读材料归入“背包”：上半部分只显示当前持有的实物，下半部分保存看过的证物和文件内容。材料记录不会因为原件送出而消失，但不属于人物／事件档案。

**当前实现 `shixu-v14-nine-hearts-seven-npcs`**：七名 NPC 的新会面均可选择“拾绪”。恐惧、同情、爱意、悲伤、愤怒、喜悦、好奇、怀疑、轻蔑共九种；任意已持有牌可对任意在场 NPC 使用。选择态度后先预览遥的实际首句，确认才消耗一张；NPC 决定逐句播放后，系统才执行材料、会面、暂停或符合原案件条件的行动。网页不再提供独立“交谈”入口，拾绪就是交谈；送礼保留，小春的整理活动仍为专属。

**对白锁定修订**：点击 NPC 仅展开选择，仍可直接换人、探索、收起或离开，不写会面记录、不完成赴约。选择“拾绪”或“送礼”才锁定人物并开始会面；拾绪成功开始时计时，送礼确认交出时计时，未交出可取消并解除锁定。仅取消人物选择／未送出的礼物，不触发 NPC 会后规划。旧 HTTP `talk` 名称兼容转入拾绪，已开始的旧对白保留；旧的未选方式存档自动回到未锁定选择页，不清档。

**心绪后果修订**：大部分出牌优先产生合法、可执行的实际后果，但不再强制每次都生成事件。没有自然合适的后果时允许继续扣牌并播放对白，不过必须结束已经回应的问题、转向来自已知现场的具体新焦点，不能换词重复追问、连续安慰或原地确认。空后果不会显示待结算状态，也不会锁住结束会面。

**跨段接话修订**：选择“继续对话／顺着聊下去”后，新段必须由上一条实际台词的另一方开口。上一拍是 NPC 就由遥接，上一拍是遥就由 NPC 接；服务端用 `turn_order` 校验并有限重试，防止人物跨段回应自己。已生成的旧段落不追溯改写。

**心绪导演 `heart-director-v1-public-context`**：每个已播选择节点最多一次额外请求，读取公开上下文并推荐 2—3 种持有牌；不重判选牌时机、不读取秘密、不替玩家决定。请求在后台进行，超时或失败也能自由选牌。未配置 AI 时明确标注固定演示，不声称在做真实戏剧性判断。

**开发观察**：会面下方折叠面板与“调试”页显示导演实际输入、推荐理由、预览与实际执行阶段；不剧透未播 NPC 回应。原理、职责、缓存和失败处理见 [16 号说明](../16_心绪导演与开发观察说明_V0.1.md)。所有已确认进度仍存档；未确认预览和导演缓存在服务重启后失效，需重新选择。预览取消不消耗游戏资源，但已发出的模型请求仍可能计费。真实 AI 的梗、推荐多样性与因果合理性须另行实测，不能用离线回归代替。

本轮 Terra 验证：320 项测试、类型检查与生产构建通过；隔离内存 HTTP 验证了推荐／预览／确认／待播／实际后果的闭环，以及旧 `talk` 请求转入拾绪、过期送礼请求不锁定人物。新增回归覆盖人物选择／取消、会面计时、赴约边界和旧存档迁移，不读写玩家实际存档。浏览器测试环境不可用，页面截图与窄屏视觉验收尚未完成；未发起真实 AI 付费采样。

以下保留早期版本的行为规则与开发记录；“仅小春／三牌”等旧范围以本节最新说明为准。

动作明确姓名（最新，`shixu-v10-named-major-actions`／普通交谈 `sunset-v7-named-major-actions`）：每句动作旁白写出实际行动者姓名，例如“雨宫小春推开门，走进屋内”；不能省略主语或仅写“她／他／你”。换行动者、两人共同动作、拆成多句时都明确姓名，不机械套用当前说话者。仍仅展示大动作，不限制正常台词人称，无额外 AI 调用；下次生成生效。

仅大动作旁白（沿用标准，`shixu-v9-major-actions-only`／普通交谈 `sunset-v6-major-actions-only`）：覆盖下方 v8 的宽松标准。只有真正改变现场的大动作才写旁白；点头、视线、呼吸、攥衣角、笑容等小动作与微表情，即使体现情绪转折也省略。取消每段 0～1 处的频率暗示，连续多段零旁白是常态，不为凑数制造动作。仍由原生成 AI 同次决定，无新增调用或判断字段；空旁白直接台词，旧待播段落不额外重写，新生成生效。

低频旁白（同日修订，`shixu-v8-sparse-narration`）：由原有对白生成 AI 在同一次请求里决定动作是否值得独立展示，默认 `stage_direction=""`。只保留影响理解、现场变化或明显情绪转折的动作；通常一段 3～5 个对白节拍配 0～1 处旁白，是生成倾向而非硬配额。空值直接播放台词，不增加点击。普通交谈／赠礼同用此提示（`sunset-v5-sparse-narration`）。无新增模型调用、评分或判断理由字段；不追加旁白频率审校。旧待播段落不额外花钱重写，下次生成生效。固定离线演示仍为测试剧本，不代表 AI 的旁白密度。

旁白与现场连续性（同日追加，`shixu-v7-narration-continuity`）：动作／微表情从台词中分离为独立旁白，逐句点“下一句”，之后才播放台词和开放选卡。后端保存旁白句号游标，刷新续读；旧档默认停在已展示的台词，不重播旧动作。实际播放的旁白单独进入记忆与跨会面现场观察，续写不把已穿鞋／已进门等动作重新当作待办。只含明确姓名冒号的混排格式做机械分离，不增加语义关键词拒绝或第二个选牌判断 AI。详见系统策划第二十一节。

测试补给（沿用旧三牌包）：网页默认给恐惧、同情、爱意 **各 3 张，共 9 张**，不随九种牌库扩展而增发。未领过该测试包的已有存档只补发一次，保留原有牌和进度；刷新或服务重启不重复发放，重新开始的新存档会再获得一套。来源标为“测试补给”，不伪装成 NPC 情绪；独立自然获取记录器仍保持无补给，避免污染资源测试。

猫神社 → 小春的新会面 → **拾绪试玩**。开场和后续都由 AI 生成，遥与 NPC 可以自然来回接话、提问及作出口头回应；只有 AI 判断末句确实需要玩家表态时才显示心绪牌。普通段落点“继续对话”；表态节点可选恐惧、同情、爱意，或“顺着聊下去”委托遥自然回应。确认出牌消耗一张，不使用问号或恐惧固定句式拦截台词。未配置 AI 时是明确标注的固定演示。

卡牌在对应 NPC 节拍实际显示时获得，生成失败不扣牌；刷新保留库存和续播位置。跨日保留，同场同种最多拾取一次。旧档为空字段兼容，不清档、不追溯发牌；正在进行的旧会面请正常结束，下一场再进入新入口。

第一天仅做小春的独立试验：原交谈与赠礼保留，材料操作仍在原交谈办理。旧拾绪段落缺少表态标记时按普通续聊兼容，下次生成用新规则，无需清档。正式美术、七人全面接入与资源平衡未完成。AI 仍可能补写往事、混淆态度或较少触发表态节点；详情和真实记录见 [系统策划第十五、十六节](../13_拾绪与心绪牌对话系统策划_V0.1.md)。

## 当前可玩内容

- 七名 NPC、八个地点、18 个物品定义：5 件日常物品、11 份初始案件材料、2 份条件生成说明。
- 初始地图仅有神社、车站、商店街。实际播放的对白／实际读到的材料说出地点，才显示地图节点。
- 已知地点没有门禁。进入地点不会自动开始会面；同场多个人物分别点击；无人地点照样可以探索。
- 移动一小时，交谈或确认赠礼两小时；礼物选择和取消不计时。场景可等待半小时，长时间等待逐节点处理事件。
- 短选项、主角与 NPC 共用对白节拍、“下一句”逐句播放并保存。一次会面最多24句显示对白（含主角），约18句进入收尾，最多5次玩家选择；随时可以提前结束。
- 前向分支对话：AI 根据本段末尾生成 2～3 个短回应，不再从固定话题池挑选。选择后不补发本次会面中错过的选项，允许自然收束。
- 查看、出示、索要、赠送分别处理。材料进手记不代表拿到实物，送出后手记保留。所有持有物品均可赠送或供奉。
- 夜间一次信仰／审美改写，公共规则进入存活 NPC 的记忆与对话，不改历史事实。
- 第七天结束生成结局与七人状态结果；AI 不可用时有事实保底，不因缺证卡关。
- 首条自主事件链：千代改口 → 可写说明或主动联系别人 → 律实际收到消息 → AI 选择接触／威胁／袭击／放弃 → 按时间与在场情况处理。
- 可在接触前、威胁阶段、袭击中或事后抵达旅馆。现场干预、离开、实际求助产生不同结果。死亡不凭空掉落遗书或补发证据。

## 存档与密钥

新章使用 `.data/sunset-case-v1.sqlite`，`saveVersion: 3`、`chapterId: sunset-case-v1`。
旧 `.data/demo-save.sqlite` 原样保留，不自动迁移或覆盖。损坏／版本不兼容的存档会报错，绝不静默清空。
“重新开始”只影响当前新章节，需网页二次确认。

已有 DeepSeek 本地配置继续从 `server/.env.local` 读取。
字段：`DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`。
真实密钥、数据库和日志均被 Git 忽略，不写进客户端或对白记录。

本机已于 2026-09-13 切换为 DeepSeek 官方接口：`DEEPSEEK_BASE_URL=https://api.deepseek.com`、`DEEPSEEK_MODEL=deepseek-v4-pro`，密钥仅填入 `server/.env.local` 的 `DEEPSEEK_API_KEY`，不再发送到 NovaAI。官方模型名不带中转平台的 `[次]` 前缀。项目使用 Chat Completions 协议，不使用 Claude 示例中的 `anthropic-messages`。可从 `.env.example` 创建本机配置；换电脑或拉取代码后，该私密文件不会自动同步。接口格式参见 [DeepSeek 官方接入说明](https://api-docs.deepseek.com/zh-cn/)。

修改配置后需重启后端；`/api/ai/status` 的 `configured` 只表示已加载密钥，真实请求成功才代表接通。已生成的固定演示段落不会因切换 API 而重写，下一次生成才使用新配置，不必清空存档。

历史 NovaAI 接入验收（2026-09-12，已停用）：Terra 确认该平台模型目录包含 `[次]deepseek-v4-pro`；在独立内存存档中通过真实拾绪开场和内容审校，共 1 次模型目录 GET、2 次生成／审校 POST，全部 HTTP 200。验证请求只发送至 `us.novaiapi.com` 并禁用重定向，未操作玩家存档；单次开场通过不等于多轮对白质量已全面验收。后续实玩出现连接及审校不可用错误，2026-09-13 按用户要求切换官方接口；不据此断言旧错误一定由密钥引起。

官方接口验收（2026-09-13）：Terra 确认模型目录与密钥可用，并在独立内存存档通过真实 `startHeartEncounter` 拾绪开场及审校；生成结果包含心绪数据，来源为 `deepseek`，没有使用演示保底。重启后 5173／8787 均已加载官方模型，玩家进度修订与状态摘要和重启前一致。测试只向 `api.deepseek.com` 发送凭据并禁用重定向，私密配置仍为 600 权限且未被 Git 跟踪；不保证后续每次网络或内容生成都成功。

## 初版边界

目前只有“千代改口”这一条完整高风险行动链，不是所有角色均能任意杀人的沙盒。
行动时间按游戏时钟推进，不按现实等待推进。其他人物不会被每晚强制轮换地点。
反思暂用会面实际见闻摘要；长期记忆按相关性、近期性、重要度检索，并非完整复现研究系统。
AI 文案校验不能等同于中文语义的绝对正确；固定材料与执行状态由系统保持权威，文学表现继续通过记录器检验。
对白和结局在结构校验后增加一次独立事实审校调用，不通过则重试或保底；这会增加一次模型请求和少量等待时间。它不能保证中文语义零错误。
美术仍为既有占位资源，本次不新增图片、不迁移 Unity。

历史版说明见 `README_旧章节参考.md`；案件设计依据见上级目录 08～11 号文档。

## 前向对话测试

提示词版本：`sunset-v4-graceful-conversation`。规则见上级目录 `12_前向分支对话规则_V0.1.md`。
现有存档兼容，不必重新开始；已经显示的旧选项不会被后台改写，下一次生成开始使用新规则。

```powershell
$env:CASE_RECORD_NPCS='npc_koharu,npc_chiyo'
$env:CASE_RECORD_ROUNDS='4'
$env:CASE_RECORD_FOLLOW='1'
npm run record:dialogues
```

`CASE_RECORD_FOLLOW=1` 自动优先选不执行物品动作的问句，只用于抽样，不影响游戏选项。
可设 `CASE_RECORD_DRAFTS=1` 附加生成草稿和审校结果（含失败候选，不能当作已发生剧情）。
记录使用内存存档，每段保留完整对白、全部选项、实际选择和错过的回应。未到收尾阶段的真实AI续聊连续失败时，报告可重试错误，保留原节点，不伪造NPC告别；已到会面预算上限才允许保底收尾。未配置AI的离线演示仍使用mock。

会面收尾专项：`npx tsx scripts/recordClosingDialogue.ts`。使用明确标注的构造前文，将预算设为已说18句，真实调用模型检查最后一段是否符合人设并结束。不是完整实玩长流程记录。
预算根据本次会面已播放事件重建，刷新和重启后不清零；显示完收尾对白后只可返回场景，不能通过出示材料／转告消息续聊。
约14句或第4次选择开始预告收尾，18句／第5次选择进入告别阶段。最后通常用2～4个节拍先回应、接住情绪，再收拾东西告别，不强迫一句话打断。
只读重放最近一次玩家选择：`npx tsx scripts/replayLastChoice.ts`，在内存副本中生成，不回写游戏。可用来区分“AI正常决定结束”和“技术失败误结束”。
