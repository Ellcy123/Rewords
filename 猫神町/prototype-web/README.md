## 拾绪 · 首日试玩（2026-09-07）

动作明确姓名（最新，`shixu-v10-named-major-actions`／普通交谈 `sunset-v7-named-major-actions`）：每句动作旁白写出实际行动者姓名，例如“雨宫小春推开门，走进屋内”；不能省略主语或仅写“她／他／你”。换行动者、两人共同动作、拆成多句时都明确姓名，不机械套用当前说话者。仍仅展示大动作，不限制正常台词人称，无额外 AI 调用；下次生成生效。

仅大动作旁白（沿用标准，`shixu-v9-major-actions-only`／普通交谈 `sunset-v6-major-actions-only`）：覆盖下方 v8 的宽松标准。只有真正改变现场的大动作才写旁白；点头、视线、呼吸、攥衣角、笑容等小动作与微表情，即使体现情绪转折也省略。取消每段 0～1 处的频率暗示，连续多段零旁白是常态，不为凑数制造动作。仍由原生成 AI 同次决定，无新增调用或判断字段；空旁白直接台词，旧待播段落不额外重写，新生成生效。

低频旁白（同日修订，`shixu-v8-sparse-narration`）：由原有对白生成 AI 在同一次请求里决定动作是否值得独立展示，默认 `stage_direction=""`。只保留影响理解、现场变化或明显情绪转折的动作；通常一段 3～5 个对白节拍配 0～1 处旁白，是生成倾向而非硬配额。空值直接播放台词，不增加点击。普通交谈／赠礼同用此提示（`sunset-v5-sparse-narration`）。无新增模型调用、评分或判断理由字段；不追加旁白频率审校。旧待播段落不额外花钱重写，下次生成生效。固定离线演示仍为测试剧本，不代表 AI 的旁白密度。

旁白与现场连续性（同日追加，`shixu-v7-narration-continuity`）：动作／微表情从台词中分离为独立旁白，逐句点“下一句”，之后才播放台词和开放选卡。后端保存旁白句号游标，刷新续读；旧档默认停在已展示的台词，不重播旧动作。实际播放的旁白单独进入记忆与跨会面现场观察，续写不把已穿鞋／已进门等动作重新当作待办。只含明确姓名冒号的混排格式做机械分离，不增加语义关键词拒绝或第二个选牌判断 AI。详见系统策划第二十一节。

测试补给（同日追加）：网页默认给每种心绪牌 **3 张，共 9 张**。已有存档自动补发一次，保留原有牌和进度；刷新或服务重启不重复发放，重新开始的新存档会再获得一套。来源标为“测试补给”，不伪装成 NPC 情绪；独立自然获取记录器仍保持无补给，避免污染资源测试。

猫神社 → 小春的新会面 → **拾绪试玩**。开场和后续都由 AI 生成，遥与 NPC 可以自然来回接话、提问及作出口头回应；只有 AI 判断末句确实需要玩家表态时才显示心绪牌。普通段落点“继续对话”；表态节点可选恐惧、同情、爱意，或“顺着聊下去”委托遥自然回应。确认出牌消耗一张，不使用问号或恐惧固定句式拦截台词。未配置 AI 时是明确标注的固定演示。

卡牌在对应 NPC 节拍实际显示时获得，生成失败不扣牌；刷新保留库存和续播位置。跨日保留，同场同种最多拾取一次。旧档为空字段兼容，不清档、不追溯发牌；正在进行的旧会面请正常结束，下一场再进入新入口。

第一天仅做小春的独立试验：原交谈与赠礼保留，材料操作仍在原交谈办理。旧拾绪段落缺少表态标记时按普通续聊兼容，下次生成用新规则，无需清档。正式美术、七人全面接入与资源平衡未完成。AI 仍可能补写往事、混淆态度或较少触发表态节点；详情和真实记录见 [系统策划第十五、十六节](../13_拾绪与心绪牌对话系统策划_V0.1.md)。

```powershell
npm run record:hearts
npm run record:heart-attitudes
```

两条命令均使用隔离内存存档及本机配置的真实 AI，不改网页进度。后者的三牌前置来源为固定演示，只验证真实 AI 对不同态度的表达，不代表自然获取分布。`HEART_RECORD_DRAFTS=1` 可额外记录前者的诊断草稿和审校反馈，不记录密钥。

当前为 `shixu-v5-forward-continuity`：本场已播对白、历史记忆和最后已播游标分开；下一段从最后一句之后续写，新会面不重播旧告别。只有生成对白的 AI 决定何时选牌，内容审校不复判时机，程序只检查节点结构与台词对应；旧的审校 `decision_point` 否决不再阻断对白。没有固定句数配额。`HEART_RECORD_TEST_PACK=1` 可让 `record:hearts` 在隔离存档获得各 3 张测试牌并依次使用三种态度；默认仍空手测自然获取。`HEART_RECORD_REVISIT=1` 在首场最多两段后主动结束，再验证新会面开场，合计最多 3 段；默认连续记录仍最多 10 段。输出长句原文重复诊断，但不拦截游戏对白。既有已播和待播内容不回写，下一次生成使用新提示。

开发者可在单独终端设 `$env:CAT_HEART_PREVIEW='1'` 后运行 `npm run dev`，得到 **5174／8790** 的固定演示、内存存档验收环境，不读写正式 SQLite。停止该环境后清除这个环境变量再启动常规 5173／8787 服务；用户试玩请使用常规入口。

## 当前可玩内容

- 七名 NPC、八个地点、18 个物品定义：5 件日常物品、11 份初始案件材料、2 份条件生成说明。
- 初始地图仅有神社、车站、商店街。实际播放的对白／实际读到的材料说出地点，才显示地图节点。
- 已知地点没有门禁。进入地点不会自动开始会面；同场多个人物分别点击；无人地点照样可以探索。
- 移动一小时，交谈或确认赠礼两小时；礼物选择和取消不计时。场景可等待半小时，长时间等待逐节点处理事件。
- 短选项、主角与 NPC 共用对白节拍、“下一句”逐句播放并保存。一次会面最多24句显示对白（含主角），约18句进入收尾，最多5次玩家选择；随时可以提前结束。
- 前向分支对话：AI 根据本段末尾生成 2～3 个短回应，不再从固定话题池挑选。选择后不补发本次会面中错过的选项，允许自然收束。
- 查看、出示、索要、赠送分别处理。材料进手记不代表拿到实物，送出后手记保留。所有持有物品均可赠送或供奉。
- 夜间一次信仰／审美改写，公共规则进入存活 NPC 的记忆与对话，不改历史事实。
- 第七天结束生成结局与七人状态结果；AI 不可用时有事实保底，不因缺证卡关。
- 首条自主事件链：千代改口 → 可写说明或主动联系别人 → 律实际收到消息 → AI 选择接触／威胁／袭击／放弃 → 按时间与在场情况处理。
- 可在接触前、威胁阶段、袭击中或事后抵达旅馆。现场干预、离开、实际求助产生不同结果。死亡不凭空掉落遗书或补发证据。

## 初版边界

目前只有“千代改口”这一条完整高风险行动链，不是所有角色均能任意杀人的沙盒。
行动时间按游戏时钟推进，不按现实等待推进。其他人物不会被每晚强制轮换地点。
反思暂用会面实际见闻摘要；长期记忆按相关性、近期性、重要度检索，并非完整复现研究系统。
AI 文案校验不能等同于中文语义的绝对正确；固定材料与执行状态由系统保持权威，文学表现继续通过记录器检验。
对白和结局在结构校验后增加一次独立事实审校调用，不通过则重试或保底；这会增加一次模型请求和少量等待时间。它不能保证中文语义零错误。
美术仍为既有占位资源，本次不新增图片、不迁移 Unity。

历史版说明见 `README_旧章节参考.md`；案件设计依据见上级目录 08～11 号文档。

## 前向对话测试

提示词版本：`sunset-v4-graceful-conversation`。规则见上级目录 `12_前向分支对话规则_V0.1.md`。
现有存档兼容，不必重新开始；已经显示的旧选项不会被后台改写，下一次生成开始使用新规则。

```powershell
$env:CASE_RECORD_NPCS='npc_koharu,npc_chiyo'
$env:CASE_RECORD_ROUNDS='4'
$env:CASE_RECORD_FOLLOW='1'
npm run record:dialogues
```

`CASE_RECORD_FOLLOW=1` 自动优先选不执行物品动作的问句，只用于抽样，不影响游戏选项。
可设 `CASE_RECORD_DRAFTS=1` 附加生成草稿和审校结果（含失败候选，不能当作已发生剧情）。
记录使用内存存档，每段保留完整对白、全部选项、实际选择和错过的回应。未到收尾阶段的真实AI续聊连续失败时，报告可重试错误，保留原节点，不伪造NPC告别；已到会面预算上限才允许保底收尾。未配置AI的离线演示仍使用mock。

会面收尾专项：`npx tsx scripts/recordClosingDialogue.ts`。使用明确标注的构造前文，将预算设为已说18句，真实调用模型检查最后一段是否符合人设并结束。不是完整实玩长流程记录。
预算根据本次会面已播放事件重建，刷新和重启后不清零；显示完收尾对白后只可返回场景，不能通过出示材料／转告消息续聊。
约14句或第4次选择开始预告收尾，18句／第5次选择进入告别阶段。最后通常用2～4个节拍先回应、接住情绪，再收拾东西告别，不强迫一句话打断。
只读重放最近一次玩家选择：`npx tsx scripts/replayLastChoice.ts`，在内存副本中生成，不回写游戏。可用来区分“AI正常决定结束”和“技术失败误结束”。
